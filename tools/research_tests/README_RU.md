# Тестовые расчёты на компьютере пользователя

Это автономный запуск исследовательского ядра 0.5.3. Основная программа
и её установленная библиотека сохраняются. Новое ядро собирается из
включённых исходников и устанавливается отдельным wheel в частную папку.
Никакие пакеты и компиляторы из сети не скачиваются.

1. Сохранить RUN_RESEARCH_TESTS.bat рядом с папкой `.venv` исходной
   установки AeroKinetic. Если скачан TXT, переименовать расширение в `.bat`.
   Если EXE лежит непосредственно внутри исходной папки программы,
   батник также проверяет `.venv` на один уровень выше.
2. Запустить двойным щелчком. Права администратора не требуются.
3. Дождаться короткой проверки, затем расчётов N32 и N64. Окно показывает
   выбранное число потоков, фазу подготовки, tU/c и Cl/Cd/Cm. Не закрывать
   его крестиком во время сохранения.
4. Отправить **AEROKINETIC_TESTS_053/FOR_REVIEW.zip** из папки рядом с BAT.
   Он создаётся и при обработанной ошибке. Гигантский checkpoint отправлять
   не требуется: он остаётся на компьютере для продолжения.

Для паузы запустить созданный файл **AEROKINETIC_TESTS_053/STOP_TESTS.bat**.
Расчёт закончится на безопасной границе шага и сохранится. Повторный
запуск RUN_RESEARCH_TESTS.bat продолжит незавершённый случай и пропустит
уже завершённый. Одновременный второй запуск блокируется файловой блокировкой.
Аварийное закрытие может потерять шаги после последнего checkpoint;
возобновление восстанавливает согласованный префикс истории.

По умолчанию: NACA0012, Re=30000, α=4°, хорда 0.15 м, момент о c/4,
периодический размах 0.5c, U_lattice=0.04, без SGS, выход 6c.
N32 — контроль реализации на другой платформе; N64 — более тонкая сетка.
Оба случая выполняются последовательно до tU/c=12 с окном статистики 6…12.
Оценка памяти N64 — около 3.23 ГиБ; учитывается дополнительный запас и
место для атомарного checkpoint. Нехватка ресурсов не уменьшает сетку.
Время на i9 заранее не обещается; серию можно оставить на длительный запуск.

Автоматически выбирается до 8 логических потоков. Настройки в начале BAT:
`AK_TEST_THREADS=auto`, `AK_TEST_GRIDS=32,64`, `AK_TEST_DURATION=12`.
Для следующей отдельной серии можно указать N128 или срок 24;
N128 оценивается примерно в 24.7 ГиБ и требует гораздо больше времени.
Перед изменением настроек переименовать прежнюю AEROKINETIC_TESTS_053,
чтобы сохранить её результаты и создать отдельную серию.

Необходим Python 3.12 x64 с закреплёнными зависимостями из исходного
комплекта. Батник ищет `.venv`, обычную установку Python312 и явный
`AK_TEST_PYTHON`. Если версии пакетов отличаются, используются существующие
локальные `downloads/wheels_windows`. Если доступен прежний переносимый
комплект с `_internal/portable/toolchain.json`, используется его компилятор;
иначе — конфигурация `pystencils.json` исходной программы.
Один старый замороженный EXE без Python и зависимостей не запускает новое
исследовательское ядро: батник явно сообщает об этом и ничего не скачивает.

Архив содержит проекты, PLAN/RUNTIME, исходные CSV, невязки, логи,
короткие проверки, описательную статистику, SVG и последний кадр сечения.
Компилятор, wheels, JIT-кэш и полные контрольные состояния не включаются.
Обмен массой стенки учитывается, а не вычитается. Текущая версия не
поддерживает Re≈6 млн; точность по продувкам остаётся неподтверждённой.
Серия из двух сеток не устанавливает порядок сходимости/GCI или DNS.

Источник опыта: Ohtake, Nakae, Motohashi (2007),
https://doi.org/10.2322/jjsass.55.439. Используются сохранённые оцифровки
Cl/Cd/Cm при Re=30000; границы маркеров не являются полной погрешностью трубы.
Полный научный контекст:
https://github.com/Bulbulator72/Aerokinetic/blob/7b53e22693b5e0971e23f0bf9770697fe1f8a5ac/docs/verification_exterior_library_20261108/REPORT_RU.md.

Для разработки и проверки на Linux:

```text
python tools/research_tests/make_transfer.py --output scratch/RUN_RESEARCH_TESTS.bat --unpack scratch/kit
python scratch/kit/bootstrap.py --kit scratch/kit --workspace scratch/run --program-root path/to/original --threads 2 --smoke
```

`--smoke` — явно обозначенная короткая проверка N16/N32 для разработчика;
BAT пользователя всегда запускает полноценную серию из своих настроек.
Windows/PowerShell/MSVC отмечаются not_run до фактического запуска там.
