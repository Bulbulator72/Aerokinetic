новая область применимости ещё не реализована и не валидирована.

Первая исследовательская версия для **трёхмерного нестационарного** обтекания
неподвижного сечения с механизацией при **Re = 10 000…100 000**. На входе —
двумерные контуры в общей системе координат. Они вытягиваются по размаху;
по размаху задаются периодические условия. Это модель участка крыла без концов,
а не конечного крыла с концевыми вихрями.

Библиотека выдаёт историю **Cl, Cd, Cm**, сохраняет поля среднего сечения и
создаёт GIF без браузера, интернета и ffmpeg. Основную программу aero2d менять
не требуется. Пример адаптера находится в `examples/integrate_aero2d.py`.

**Точность по продувкам пока не подтверждена.** Проверены численное ядро,
вязкость, сохранение массы и импульса, положение криволинейных стенок,
симметрия сил, баланс давления и работа двух элементов. Демо имеет грубую
сетку и короткое время: его коэффициенты нельзя использовать как поляру.

## Метод и его смысл

Используется метод решёточного Больцмана **D3Q27 с кумулянтным оператором**
из lbmpy 1.4. Криволинейные неподвижные стенки — линейная интерполяция
Bouzidi. Давление и вязкое сопротивление входят в обмен импульсом на стенках.
Момент вычисляется по тем же связям сетки, относительно заданной точки.

LBM описывает функции распределения, а не отслеживает реальные молекулы.
Для обычного атмосферного воздуха на этих масштабах его гидродинамический
предел — уравнения Навье—Стокса. Метод даёт другой вычислительный подход;
точность определяют также сетка, границы, третье измерение и статистика.
DSMC для разреженного газа здесь не выбран из-за малого Kn и малых скоростей.

По умолчанию явная подсеточная модель выключена (`sgs="none"`). Это означает
отсутствие явной SGS-модели, **а не автоматическое разрешение всех масштабов**.
Можно включить `sgs="smagorinsky"`, коэффициент по умолчанию 0.10. В таком
расчёте мелкие масштабы моделируются. У этой модели нет динамического
определения коэффициента, пристенной поправки и модели перехода. Их влияние
на ламинарный пузырь и переход нужно оценивать отдельно. Начальное малое
трёхмерное возмущение запускает неустойчивости; оно не заменяет заданный
спектр турбулентности аэродинамической трубы.

## Подготовка дома и установка без интернета

Для переносимой папки с `AeroKinetic.exe` подготовлен отдельный
[сценарий домашней сборки](docs/BUILD_PORTABLE_RU.md). Он использует рабочий
домашний Windows/компилятор и создаёт новый комплект, сохраняя старую
установку. Сборка и проверка на целевой Windows-машине ещё необходимы;
подготовленный сценарий не является уже проверенным Windows EXE.

Базовый автономный комплект предназначен для **Windows x64 и Python 3.12**.
Версии всех Python-зависимостей закреплены в `requirements-offline-py312.txt`.
Первый запуск компилирует ядро локально, поэтому нужен компилятор C++.

На компьютере с интернетом:

1. Распакуйте архив в короткий путь, например `C:\aerokinetic`.
2. Запустите `1_download_ONLINE_WINDOWS.bat`. Если Python 3.12 отсутствует,
   BAT скачает установщик и предложит установить его, после чего повторите BAT.
3. Если на рабочем компьютере нет Visual Studio C++ Build Tools, запустите
   `1b_download_COMPILER_ONLINE.bat`. Он создаёт полный автономный layout
   Visual Studio 2022 C++ — потребуется несколько гигабайт.
4. Скопируйте **всю папку**, включая `downloads`, на рабочий компьютер.

На рабочем компьютере:

1. При необходимости запустите `0_install_PYTHON_OFFLINE.bat`.
2. При необходимости запустите `2_install_COMPILER_OFFLINE.bat`.
   Установщик может запросить права администратора и перезагрузку.
3. Запустите `3_install_WINDOWS_OFFLINE.bat`: проверка SHA-256 файлов,
   установка с `--no-index`, проверка зависимостей и численные тесты.
4. Запустите `4_run_PREVIEW.bat` для проверки расчёта и анимации.

Python-зависимости Windows проверены скачиванием целевого wheelhouse.
Сами BAT и MSVC-путь подготовлены, но **не запускались на Windows** в этой
среде. Численные тесты и демонстрация выполнены на Linux CPU.
Установка Scite/Firecrawl в ChatGPT не нужна для работы библиотеки.

Для Linux/WSL x86_64 есть `1c_download_LINUX_WHEELS_ONLINE.bat` и
`tools/install_linux_offline.sh`. На целевом Linux заранее должны быть
Python 3.12, его заголовки, venv и g++. Системный Linux toolchain этим BAT
не скачивается. CPU — проверенный путь. В коде есть экспериментальный GPU
target через CuPy/CUDA; он не проверен на видеокарте и не включён в базовый
автономный lock-файл. Для воспроизводимого первого запуска используйте CPU.

## Быстрый запуск

После установки Windows команды выполняются через `.venv\Scripts\python.exe`;
в Linux — через `.venv/bin/python`.

```text
python -m aerokinetic.cli plan examples/naca0012_preview.json
python -m aerokinetic.cli run examples/naca0012_preview.json --output run01 --animate
python -m aerokinetic.cli animate run01 --field speed
```

`plan` показывает размер сетки, фактическую длину периодического размаха,
вязкость, шаг времени и **оценку памяти до выделения массивов**. Лимит памяти
задаётся явно. Если оценка выше лимита, Solver останавливается. Оценка не
заменяет измерение пикового потребления на целевой машине.

`examples/naca0012_re30000_plan.json` — пример параметров для планирования
исследования разрешения. Он требует около 9 ТиБ на равномерной сетке и при
лимите 8 ГиБ **не запускается**. Даже 512 ячеек на хорду не являются
заранее доказанным достаточным разрешением. Для практического точного расчёта
на обычном компьютере добавлено локальное сгущение сетки в отдельном режиме.
Снижение разрешения меняет точность, а не заданный Re.

В новом режиме одновременно работают крупный и мелкий уровни с локальным
согласованием потоков. Все стенки находятся на мелком уровне; силы
учитывают оба его подшага. Это исследовательская реализация, без SGS,
GPU и подтверждённой сходимости аэродинамических характеристик.
См. [первый этап](docs/REFINEMENT_RU.md),
[пространственный стык](docs/INTERFACE_RU.md) и
[актуальную дорожную карту](docs/ROADMAP_RU.md).

Для короткой проверки двух уровней откройте в окне
`examples/naca0012_refined_re30000_preview.json` либо выполните:

```text
python -m aerokinetic.cli plan-refined examples/naca0012_refined_re30000_preview.json
python -m aerokinetic.cli run-refined examples/naca0012_refined_re30000_preview.json --output refined01 --animate
```

Этот пример даёт 32 ячейки/хорду вдали и 64 у тела, tU/c=0.2.
Он проверяет запуск и вывод полей; переходный процесс ещё не исключён.

## Встраивание

```python
from aerokinetic import Section, Flow, Grid, Plan, Solver
from aerokinetic.animation import animate

# af или elements берутся из aero2d. Контуры каждого элемента уже должны
# находиться в общей системе координат, со всеми отклонениями и смещениями.
section = Section.from_aero2d(elements)
flow = Flow(reynolds=30000, alpha_deg=5.0, physical_chord_m=0.15)
grid = Grid(cells_per_chord=32, upstream_chords=1.5,
            downstream_chords=3, transverse_chords=1.5,
            span_chords=0.5, memory_limit_gib=2)
print(Plan.create(section, flow, grid).as_dict())

# Эта грубая сетка — пример интерфейса. Для инженерных коэффициентов
# параметры выбирают по исследованию сходимости.
solver = Solver(section, flow, grid)
result = solver.run(duration_convective=2, output="run02",
                    average_after=1, sample_every=20, frame_every=200)
animate("run02")
```

Адаптер принимает один `Airfoil` или список `Airfoil` из aero2d. Полный
перечень контуров без зависимости от aero2d можно создать через `Contour(xy)`.
Нормировка не применяется к элементам по отдельности. Самопересечения,
касание и пересечение элементов запрещаются.

Минимальный зазор должен разрешаться несколькими **жидкими** ячейками,
пограничные слои — значительно большим числом. Проверяйте маску тел,
уменьшайте dx, сравнивайте формы щелей. Общий автоматический критерий
достаточности зазора в этой версии не реализован.

## Хорда, угол, время и знаки

- Автоматическая **полная опорная хорда** — расстояние от самой передней
  точки сборки до самой задней точки; при двух задних точках одной абсциссы
  берётся их средняя ордината. Учитываются предкрылок и закрылок. Можно
  передать `Section(..., chord=...)` явно. Координаты хранят свои единицы;
  физическая хорда в метрах задаётся отдельно.
- Автоматическая точка момента — четверть этой полной хорды. Для другого
  соглашения передайте `moment_reference=(x,y)` в единицах исходных контуров.
- `alpha_deg` отсчитывается от **оси x исходного файла**, обычно хорды
  основной части; положительный угол поднимает нос. Автоматически пересчитывать
  угол относительно повёрнутой линии «нос—закрылок» библиотека не будет.
- **Cl** положителен вверх, **Cd** — вдоль набегающего потока, **Cm** — на
  кабрирование. Площадь нормировки `c * periodic_span`, нормировка момента
  `q * c² * periodic_span`. Это коэффициенты сечения, усреднённые по размаху.
- Без заданной физической хорды история времени имеет **t* = t U/c**.
  Стандартная атмосфера: 288.15 K, 101325 Pa, μ = 1.7894·10⁻⁵ Pa·s,
  ρ ≈ 1.225 kg/m³. При `physical_chord_m` скорость вычисляется из Re и
  появляется время в секундах. Физические Ma > 0.15 и Kn > 10⁻³ отклоняются.
- Решёточная скорость — численный параметр. Уменьшение её при постоянных
  Re и разрешении проверяет ошибку слабой сжимаемости; это не изменение
  физической скорости. Контролируется также **локальный** решёточный Ma.

## Файлы результата

`history.csv` содержит время и мгновенные Cl/Cd/Cm, локальное максимальное Ma
и максимальное отклонение плотности. Силы относятся к середине интервала
переноса импульса. Кадры — к целому шагу времени.

`metadata.json` сохраняет геометрию, режим, сетку, соглашения и статус;
`summary.json` — среднее после `average_after`, RMS пульсаций и статус.
RMS **не является** доверительным интервалом среднего. Начальный переходный
процесс необходимо исключать по установлению статистики, а не по числу
итераций. Новые расчёты записываются только в новую или пустую директорию.

`frames/*.npz` содержит скорость/U, Cp и ωz·c/U в средней плоскости
трёхмерной области. Это **срез**, а не трёхмерная изоповерхность вихрей.
GIF хранится локально. Горизонт рисунка и размер кадров можно менять в
`save_frame`. Область твёрдых тел маскируется.

При NaN/Inf, локальном Ma > 0.3 либо |ρ−1| > 0.1 расчёт получает статус
`failed`; средние коэффициенты для такого расчёта не публикуются. Это
контроль численной пригодности, а не доказательство точности. Версия 0.2
сохраняет CPU-состояние и продолжает исходную историю через
`python -m aerokinetic.cli resume <папка>` либо окно программы.

## Эталон и проверка точности

Основной первичный источник: **Ohtake, Nakae, Motohashi (2007)**,
*Nonlinearity of the Aerodynamic Characteristics of NACA0012 Aerofoil at
Low Reynolds Numbers*, DOI [10.2322/jjsass.55.439](https://doi.org/10.2322/jjsass.55.439).
Он охватывает именно Re = 10⁴…10⁵ и содержит Cl, Cd и Cm(c/4).
Сведения об условиях и ограничениях сверки — в `references/README_RU.md`.

В комплекте есть PDF и **115 оцифрованных маркеров Cl при Re=30000 из рис.5**,
CSV, информация о происхождении и скрипт воспроизведения извлечения.
Это оцифровка графика с приблизительными границами погрешности ±0.12° и
±0.008 по Cl. Это не исходная таблица авторов и не погрешность самой продувки.
Cd и Cm пока доступны в PDF; их численная оцифровка не выполнена.

```text
python benchmarks/compare_cl.py run_a5 run_a8 --output comparison.csv
```

Команда сравнивает средние Cl с интерполированной экспериментальной кривой
при Re=30000. Экстраполяция запрещена. Она вычисляет разности и **не** ставит
автоматический знак «точность подтверждена».

Перед инженерным применением необходимы:

1. Сходимость по dx и разрешение пристенных слоёв, щелей и следа.
2. Независимость от размеров внешней области и положения выходной границы.
3. Независимость статистики от периодического размаха и разрешения по нему.
4. Проверка при уменьшении решёточного Ma.
5. Исключение разгона потока, достаточное время усреднения, оценка временной
   корреляции и статистической неопределённости.
6. Согласование геометрии задней кромки, шероховатости, фоновой турбулентности,
   хорды и момента с опытом. В механизации — отдельная проверка зазоров.
7. Сверка **всех трёх** коэффициентов в нескольких режимах, включая переход
   и отрыв. Проверка чистого NACA0012 не валидирует автоматически механизацию.

Внешние условия сейчас: заданная скорость слева, сверху и снизу, экстраполяция
выхода справа, периодичность по z. Дальняя граница не моделирует стенки трубы
и не содержит вихревой поправки для подъёмной силы. Сильный обратный поток на
выходе непригоден для такого выходного условия — область следует расширить.
