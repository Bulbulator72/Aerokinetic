# Автономная сборка и проверка поставки

## Контракт поставки

Библиотека при импорте, локальной JIT-компиляции, расчёте и создании
анимации не должна загружать данные или зависимости из интернета.
Отдельный этап подготовки на компьютере с интернетом допускается.
Фиксируй платформу, архитектуру, Python ABI, backend и его аппаратные
требования. Подготовка одного target не подтверждает работоспособность другого.

Совместимость с более новым pystencils должна быть отдельно проверена.

## Подготовка с интернетом

1. Подготовь полное транзитивное замыкание зависимостей, включая условные
   Windows-зависимости, build backend и необходимые тестовые/графические
   пакеты. Закрепи проверенные версии. Используй бинарные wheels нужного ABI.
2. Построй wheel самой библиотеки из проверенного состояния кода.
   Сверь исходники в wheel с теми, на которых выполнялись проверки.
3. Создай манифест имён, размеров и SHA-256. Запиши версии и происхождение
   пакетов; не включай учётные данные, окружение с секретами и личные кеши.
4. Учти Python, C++ toolchain, заголовки Python, системные библиотеки,
   при необходимости CUDA runtime/компилятор и драйвер. Python wheels сами
   по себе не составляют весь машинный комплект.
5. Для требуемых новых компонентов подготовь воспроизводимые BAT/скрипты
   скачивания и установки. Размер, права администратора, необходимость
   перезагрузки и неавтоматизированные шаги укажи конкретно.

Используй существующее авторизованное окружение; не меняй рабочую систему
пользователя и не устанавливай системные компоненты без основания в задаче.
Создание BAT и локальной изолированной среды входит в обычную подготовку
поставки и не требует нового согласования на каждый файл.

## Проверка без сети

Используй новую чистую venv без доступа к системным site-packages. Не
используй сетевые обходы. Докажи отсутствие нужды в сети отключённым
доступом на уровне среды либо зафиксированным контролем обращений.
`--no-index` и локальные wheels обязательны, но отдельно ещё не доказывают
отсутствие сетевого обращения внутри JIT, графики или runtime.

Из корня проекта, в подходящем активном чистом окружении:

```text
python tools/verify_offline.py downloads/wheels_windows
python -m pip install --no-index --find-links downloads/wheels_windows -r requirements-offline-py312.txt
python -m pip install --no-index --find-links downloads/wheels_windows aerokinetic==0.2.0
python -m pip check
python -m pytest -q -o pythonpath=
```

Для Linux используй `downloads/wheels_linux`. При изменении версии подставь
текущую версию; существующий пример 0.2.0 не требует постоянного сохранения
этого номера. До установки проверь наличие toolchain. Явно проверь путь
импортируемого пакета: он должен вести в установленный wheel, а не в `src`
через editable-install, PYTHONPATH или настройки тестов.

Дополнительно выполни короткий расчёт с новой пустой выходной папкой,
проверь конечные поля, историю Cl/Cd/Cm, metadata/summary, NPZ и GIF.
Повторное имя существующей папки не должно смешивать результаты.
Первую компиляцию выполняй с чистым целевым кешем: старый скомпилированный
кеш может скрыть отсутствие нужного компилятора или заголовков.

Демонстрация на грубой сетке подтверждает запуск, не аэродинамическую
точность. Результаты Windows/MSVC или GPU отмечай `not_run`, если они не
выполнялись на соответствующей платформе. Скачивание Windows-wheels на
Linux не меняет этот статус.

## Состав архива

Включи код, лицензию, pyproject, lock, инструкции, BAT/скрипты, тесты,
примеры, научные источники с происхождением и проектный навык:
`AGENTS.md`, `.agents/skills/cfd-lbm/SKILL.md`, его ссылки и шаблоны.
При заявленном готовом wheelhouse включи его манифест и все перечисленные
файлы. Проверь архив на целостность и согласованность с проверенным кодом.

Не включай venv, сборочные кеши, сломанные пробные прогоны, ключи и
неотносящиеся файлы. Исторические научные данные не перелицензируются
автоматически как код. Текущий проект использует GPL-3.0-or-later;
сохраняй лицензии включённых компонентов.

Изменение только проектного навыка выпускай отдельным переносимым архивом
с инструкцией наложения на проект. Оно не требует пересборки численного
wheel, скачивания тех же зависимостей или нового CFD-прогона.
