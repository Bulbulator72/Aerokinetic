# Выбор оболочки и архитектура

## Решение о технологии

Tkinter/ttk — существующая реализация. Разрешены PySide6/Qt, другая
настольная библиотека или полностью локальная веб-оболочка. Выбирай под
пользовательские задачи и проверяемую поставку, а не по названию технологии.
Смена оболочки не требует нового разрешения пользователя.

Для крупного обновления сохрани краткое решение в `docs/`:

| Что оценить | Как подтвердить |
|---|---|
| Панели, разделители, дерево проекта, формы и таблицы | Прототип основного рабочего экрана с реальными данными |
| Графики, сетка и изображения | Встроенный график, масштабирование, выбор кадра и экспорт |
| Windows и высокие DPI | Официальная совместимость выбранной версии; затем проверка на целевой ОС |
| Отзывчивость | Фоновая задача, очередь событий и измерение задержек действий |
| Автономность | Все транзитивные зависимости и ресурсы доступны локально |
| Цена перехода | Перечень переносимых функций, риск форматов/продолжения, путь возврата |
| Лицензии и размер | Лицензии включаемых компонентов, объём дистрибутива и требования среды |

Зафиксируй кандидатов, выбранный вариант, точные версии и причину выбора.
Используй официальную документацию для версионной совместимости/API;
отмечай непроверенные свойства отдельно. Внешние плагины для макетов
не подтверждают способность сгенерировать работающее настольное приложение.

Минимальный прототип выбора включает загрузку существующего Project,
отображение сохранённой истории/поля и обработку фоновой операции.
При новых зависимостях проверь локальную установку и запуск; на недоступной
платформе сохрани `not_run` и продолжай доступную разработку.
Согласованный с пользователем приоритет автономности сохраняется.

## Границы компонентов

- **Представление:** окна, панели, элементы ввода, темы, графические виджеты.
- **Модель проекта:** типизированные настройки, валидация, черновик и
  сериализация. Не связывай модель с Tk/Qt-переменными.
- **Контроллер выполнения:** команда запуска/остановки, события, ошибки,
  пути результатов и допустимые переходы состояний.
- **Ядро:** существующий расчётный API, checkpoint и численные результаты.
  CLI и импорты вычислительного пакета работают без создания GUI.

Переиспользуй существующие Project, RunSettings, StopCriteria, mesh planner
и средства анализа вместо копирования их формул в новую форму. Одно
поле формы должно иметь явное соответствие сохраняемому параметру.
Скрытые параметры проекта, геометрия и опорная хорда сохраняются.

Для GUI нужны собственные настройки расположения панелей/темы; не включай
их в численную идентичность checkpoint. Не подменяй входы расчёта
настройками отображения.

## Фоновая работа

Не выполняй длительную компиляцию, выделение сетки, численные шаги,
загрузку больших полей и экспорт в цикле обработки событий интерфейса.
Выбери поток или процесс с учётом фактического поведения GIL, JIT и данных;
не обещай отзывчивость только по наличию `threading.Thread`.

Виджеты меняются только из GUI-потока. Рабочий исполнитель публикует
неизменяемые сообщения/снимки через очередь, сигнал или другой ограниченный
канал. Ограничивай частоту перерисовки и размер очереди; промежуточные кадры
можно объединять для экрана, сохраняя заданную запись расчётных данных.

Отдельный процесс на Windows использует совместимый запуск и защиту
точки входа. Перед переходом проверь завершение дочерних процессов,
доставку исключений, сохранение и пути с пробелами/кириллицей.
Не запускай Tk и Qt в одном процессе с независимыми циклами событий.

Не копируй полные 3D-массивы на каждый экранный тик. Передавай нужное
сечение/малый снимок либо читай уже сохранённый кадр. Учитывай CPU-потоки
решателя и стоимость графики; отзывчивость GUI измеряй под нагрузкой.

## Совместимость при переносе

Сохраняй старые JSON и результаты. Если формат нужно расширить, читай
старую версию с явными значениями по умолчанию и проверяй roundtrip.
Старые исходные файлы не переписывай при открытии. Для сохранения изменений
используй явный путь/действие и атомарную замену там, где она поддерживается.

Перед заменой точки запуска должен работать целый сценарий: проект →
план сетки → реальный короткий расчёт → остановка/продолжение → результаты
→ экспорт. При переходе сравни переданные ядру настройки и существующие
данные, а не только внешний вид двух окон.

Не копируй зависимости или JIT-кеш с домашнего ПК вместо автономного
дистрибутива. Новая оболочка не устраняет потребность текущего ядра в
совместимом локальном компиляторе. Диагностика MSVC остаётся отдельной.
