# Проверка интерфейса и автономной поставки

## Объём проверки

Выбирай проверки по влиянию изменения. Для текста/стиля достаточно
осмотра нужных состояний и компоновки. Для связей полей с проектом нужны
сохранение/загрузка и проверка реальных переданных параметров. Для фонового
выполнения нужны запуск, остановка, ошибки и продолжение. При смене GUI
проверь полный основной сценарий и установленную поставку.

Не создавай тесты, повторяющие номера строк, конкретные отступы и устройство
виджета. Автоматизируй существенные контракты данных и воспроизводимые
регрессии. Для экранных свойств сохраняй снимок реального интерфейса.
Playwright и браузерные тесты применимы к веб-интерфейсу; они не проверяют
нативные окна Tk/Qt. Выбирай инструмент под фактическую оболочку.

## Минимальные сценарии

| Область | Наблюдаемая проверка |
|---|---|
| Проект | Открыть старый JSON, изменить нужное поле, сохранить и открыть; прочие параметры сохранены |
| Геометрия | NACA и импорт нескольких контуров; масштаб и система координат совпадают с данными |
| Ввод | Пустое/неконечное/неверное значение, научная запись, политика десятичной запятой; понятное исправление |
| Сетка | Черновик, построение, применение/отмена, реальное разрешение, границы уровней и оценка памяти |
| Расчёт | Валидные параметры дошли до ядра; состояния и доступность действий соответствуют выполнению |
| Фон | Перемещение/изменение размера окна, просмотр графика и остановка работают при нагрузке |
| Невязки | Четыре компоненты, L2/L∞, пороги, сохранение условий и верная причина остановки |
| Продолжение | Штатная остановка, повторное открытие и доступное продолжение; история не дублируется |
| Анализ | Открыть старый результат без его изменения, выбрать окно статистики, увидеть исходные и средние значения |
| Поле/экспорт | Реальный кадр с корректной шкалой, временем и единицами; PNG/CSV/GIF соответствуют выбору |
| Ошибки | Недоступная папка, неверный проект, отсутствующий результат/компилятор; журнал и доступное действие |
| Завершение | Закрытие дополнительного окна не завершает расчёт; выход во время работы сохраняет штатное состояние |

Для миграции сравни настройки, переданные тому же ядру, и отображение
того же сохранённого набора. Короткий реальный расчёт подтверждает связность
GUI и ядра, а не физическую точность.

## Размер окна, DPI и доступность

Принимаемые ориентиры компоновки: 1280×720 при 100%, 1920×1080 при 125%
и 150%; при 200% все основные действия остаются доступны через адаптивную
компоновку/прокрутку. Это целевые проверки, а не утверждение о текущей
поддержке. По возможности проверь перенос между мониторами с разным DPI.

Проверь отсутствие обрезанных русских подписей, поведение разделителей,
прокрутку, логичный порядок Tab/Shift+Tab, видимый фокус, клавиатурное
открытие/сохранение, Escape/отмену и отсутствие зависимости только от цвета.
Оцени взаимодействие с системным масштабом/темой на Windows отдельно.
Клавиатурные проверки не доказывают поддержку экранного диктора; для
такого заявления нужна самостоятельная проверка.

Отзывчивость проверяй во время компиляции/расчёта/экспорта. Измеряй задержки
и память в реалистичной нагрузке; порог выбирай заранее под сценарий.
Не изменяй численный шаг или частоту записи ради прохождения UI-проверки.

## Автономный запуск

При новых зависимостях следуй
[протоколу автономной сборки](../../cfd-lbm/references/offline.md).
Проверь установленный пакет в чистой среде без сети с пустым нужным кешем.
В комплект входят библиотеки, платформенные плагины, шрифты/иконки и другие
ресурсы, фактически нужные выбранной оболочке. Сохраняй лицензии и SHA-256.

Целевая среда пользователя — Windows x64, полный Python 3.12, существующие
проекты и расчётное ядро. Новая оболочка не должна добавлять облачную
авторизацию, сетевую проверку лицензии, обязательный внешний сайт или
неподготовленные runtime-загрузки. Для новых компонентов подготовь понятные
этапы «скачать дома» и «установить/запустить на работе».

Native Windows GUI/MSVC, Linux GUI, headless CLI и GPU проверяются отдельно.
Отключённый доступ к сокетам Python сам по себе не доказывает отсутствие
сетевых обращений нативной GUI-библиотеки или браузерного движка.
Указывай фактически действующий способ сетевой изоляции и его границы.

## Запись результата

Для содержательного изменения сохрани в новой папке `docs/verification_ui_*`
краткий отчёт: ожидаемое поведение, версия/изменённые файлы, ОС/GUI/backend,
зависимости, команды, сценарии, снимки, результаты и нерешённые ограничения.
Статусы: `passed`, `failed`, `not_run`, `inconclusive`, `not_applicable`
с объяснением последнего. Исторические доказательства не переписывай.

Отдельно укажи состояние реализации GUI, сохранности/совместимости данных,
отзывчивости, Windows/DPI и автономного запуска. Не объединяй их с
аэродинамической валидацией в один зелёный статус.

Для изменения только навыка/документации достаточно проверки структуры,
front matter, относительных ссылок, подключения в AGENTS и включения файлов
навыка в новую исходную поставку. Численный расчёт для этого не требуется.
