# Проверка компьютера и входной постановки

## Отчёт Windows

Запустите из папки проекта [5_check_hardware_WINDOWS.bat](../5_check_hardware_WINDOWS.bat).
Он вызывает локальный PowerShell, получает ОС, CPU, общую/свободную RAM,
имя NVIDIA GPU, полную/свободную VRAM, версию драйвера и место на диске
проекта, затем записывает `hardware_windows.json`.

Скрипт ничего не устанавливает и не запускает расчёт. Python и интернет
не требуются. Наличие `nvidia-smi` зависит от установленного драйвера;
если его нет или запрос не удался, GPU остаётся непроверенным в отчёте.
Имя компьютера, имя пользователя, серийные номера и переменные окружения
не собираются. Исходник — [collect_hardware_windows.ps1](../tools/collect_hardware_windows.ps1).
На Windows этот скрипт в данной среде ещё не выполнялся.

## Планировщик физического режима

Нужен только Python стандартной библиотеки. Из корня проекта:

```text
python tools/plan_case.py --reynolds 1e8 --mach 0.4 --alpha-deg 30
python tools/plan_case.py --chord-m 1 --speed-m-s 30
```

Первый пример вычисляет соответствующие стандартной атмосфере скорость
и хорду. Второй — Re и M для физического размера и скорости. Дополнительные
входы разрешены, если они согласованы; противоречия отклоняются.
Скорость и Mach сами по себе не задают два независимых масштаба.

Например, `--reynolds 1e8 --chord-m 1` отклоняется, потому что при ISA
получающийся Mach превышает 0.4. Геометрия не растягивается скрытно, чтобы
поместить такой случай в ограничение.

Поля `matches_legacy_solver_input_limits` и `solver_executed` разделяют
планирование и CFD. Принятые планировщиком входы не означают, что новый
сжимаемый решатель уже реализован или что аэродинамическая точность доказана.
Вызов CFD в этом инструменте отсутствует.
