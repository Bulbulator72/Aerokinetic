# AeroKinetic 0.2.1: средние и пульсации

Вкладка «Средние» показывает Cl/Cd/Cm в сохранённом временном окне:
среднее, RMS пульсаций, средние первой и второй половин и их разность.
Графики ниже показывают средние по последовательным блокам. Блоки могут
быть коррелированы, а короткий блок — разрезать период колебаний.

На графике полной истории оранжевая линия показывает накапливаемое
среднее после исходной отсечки расчёта. Она не сглаживает мгновенные данные.
Выполнение заданной длительности подписывается отдельно от сходимости.
При открытии результата поля режима и геометрии показывают параметры
именно этого сохранённого расчёта.

## Обновление уже установленной программы

1. Закройте окно AeroKinetic.
2. Сохраните **весь** `UPDATE_AEROKINETIC.txt` как `UPDATE_AEROKINETIC.bat`
   в существующую папку программы рядом с `6_run_AEROKINETIC.bat` и `.venv`.
   Проверьте, что расширение получилось `.bat`, а не `.bat.txt`.
3. Запустите этот BAT. Интернет, новые зависимости и установка компилятора
   не требуются. Обновляется приложение в уже установленном окружении.
4. Откройте программу обычным `6_run_AEROKINETIC.bat`. В заголовке — **0.2.1**.
5. Нажмите «Открыть результат…», выберите папку расчёта и вкладку «Средние».

Отсечка по умолчанию берётся из `summary.json`. Её изменение на вкладке
влияет только на отдельный анализ и отчёт: не изменяет исходную историю,
сохранённое среднее или сравнение с продувкой во вкладке «Продувки».
Для отчёта нажмите **«Отчёт и архив для проверки»**. Появится новая подпапка
`analysis_…` с `REPORT_RU.txt`, `forces.png`, `temporal_diagnostics.json`
и **`FOR_REVIEW.zip`**. Для разбора достаточно прислать последний файл.
Он содержит исходную историю и параметры, один последний кадр и отчёт;
большое контрольное состояние и все остальные кадры не включаются.

В текстовом отчёте есть RMS для каждой половины окна: можно измерить,
уменьшились ли пульсации. Это не устанавливает их физическую причину.
RMS не равен погрешности среднего. Автоматического статуса «сошлось» нет:
для него необходимы критерий, достаточная статистика и проверки численной
неопределённости. Подробнее — `docs/TEMPORAL_DIAGNOSTICS_RU.md`.

## Резервная копия и автономность

В `updates/update_0.2.1_…` остаются проверенный wheel, исходники, журнал
`install.log` и `backup`. До установки проверяются SHA-256 всех файлов,
сохраняются прежний установленный пакет и заменяемые исходники.
При ошибке установки восстанавливается резервная копия. Файлы проектов,
расчётные папки и контрольные состояния обновление не изменяет.
В уже подготовленную папку `downloads/wheels_windows` (или `wheels_linux`)
также добавляются новый wheel и его SHA-256, чтобы повторная автономная
установка оставалась работоспособной. Сторонние зависимости прежние.

Для ручного возврата в терминале папки программы:

```text
.venv\Scripts\python.exe updates\update_0.2.1_…\install_update.py --root . --restore updates\update_0.2.1_…\backup
```

Подставьте настоящее имя подпапки вместо `update_0.2.1_…`. Прежде закройте
программу. Обновление предназначено для существующей версии 0.2.0/0.2.1
с закреплёнными зависимостями; оно не является полной новой установкой.

Для автоматизации:

```text
python -m aerokinetic.cli analyze path/to/run --average-after 1
```

## Проверки и границы

Критерии до проверки сохранены в `docs/verification_021/PLAN.json`.
Итоги исполнения и контрольные суммы — в `docs/verification_021/CHECKS.json`.
Проверяются аналитические сигналы, настоящий интерфейс Tk, установленный
wheel, неизменность исходных результатов и установка без индекса пакетов.
Windows BAT/PowerShell в этой Linux-среде не запускался.

Численный решатель, стенки, сетка, параметры SGS и нормировка сил прежние.
Сетка остаётся равномерной. Применимость текущего прототипа — Re=10⁴…10⁵,
M∞≤0.15. Пространственная/статистическая сходимость пользовательского
расчёта и аэродинамическая точность по продувкам этим обновлением не
подтверждаются. Следующий этап повышения разрешения — локальное сгущение
с верификацией обмена на границах уровней.
