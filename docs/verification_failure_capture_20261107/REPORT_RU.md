# Воспроизведение NumericalFailure без изменения исходного расчёта

7 ноября2026. Новый инструмент `tools/capture_failure.py` проверен
на установленном wheel выпущенной **0.5.1**. Он не меняет численное ядро
или пороги допуска и не требует новых зависимостей.

```text
python tools/capture_failure.py FAILED_RUN --output NEW_DIAGNOSTIC_FOLDER
```

Нужен более ранний допустимый checkpoint равномерной CPU-сетки и запись
NumericalFailure в metadata. Папка вывода должна быть новой и располагаться
вне исходного расчёта. Для крупного диагностического массива есть
`--save-pdfs`; этот файл намеренно не является checkpoint для продолжения.

Инструмент восстанавливает сохранённое состояние исходной библиотекой,
делает шаги с исходной частотой проверок и сохраняет сечение в плоскости
максимального Ma при аварии. Он проверяет совпадение **шага и текста
исключения**, а также SHA-256 всех родительских файлов до/после. Большие
файлы хешируются потоково. Средние по недопустимому состоянию не вычисляются.
GUI и расчётные операторы этим дополнением не изменяются.

## Реальная проверка на0.5.1

Заданы две встречные акустические плотностные гауссовы моды на грубой
равномерной сетке. Каждая исходная амплитуда0.085 по отдельности меньше
предела |ρ−1|=0.1; начальное состояние прошло действующую диагностику.
При столкновении их сумма привела к **настоящему NumericalFailure**.
Условие останова не подменялось и исключение не имитировалось.

Это специально заданный тест диагностики. Он не является продувкой,
проверкой точности NACA0012 или предложенным начальным условием рабочего
расчёта. Начальное поле отдельно описано в [INITIAL_CONDITION.json](INITIAL_CONDITION.json).

Сбой произошёл на шаге4. По сохранённому допустимому checkpoint шага3
он воспроизведён на шаге4 с тем же исключением; родительские файлы
побайтово неизменны. Числа, версии, исходные и выходные SHA-256:
[CHECKS.json](CHECKS.json). В NPZ лежит недопустимое сечение для диагностики.

Повторение на0.5.1 с установленными закреплёнными зависимостями:

```text
python docs/verification_failure_capture_20261107/reproduce.py --output NEW_TEST_DIRECTORY
```

Большой checkpoint остаётся в workspace, его SHA-256 указан в CHECKS.
Повторная генерация NPZ может дать другой хеш ZIP-контейнера из-за
служебного времени; для воспроизведения важны исходное поле, код, среды,
численная траектория и реальное срабатывание исходного критерия.

Дополнительно в исследовательском кандидате0.5.2 воспроизведены аварии
профиля точно на шагах5192 и6640. Обе показали максимум Ma у выходной
границы. Это результат локализации ошибки, а не подтверждение точности
отклонённых характеристических условий. Их данные и отчёт сохраняются
в ветке research/characteristic-farfield-20261107.

Публикационная копия: новые двоичные сечения, изображения и промежуточные wheel остаются в workspace после отказа автоматической проверки разрешений на бинарную выгрузку. Научный MANIFEST_SHA256 описывает исходный локальный снимок; точный публичный состав и хеши этих текстов отражены в publication/FILES_SHA256.json, исключения — в publication/EXCLUDED_FILES.json. Числовые CSV/JSON и исходники опубликованы.
