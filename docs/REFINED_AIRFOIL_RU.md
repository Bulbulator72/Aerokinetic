# Неподвижный профиль на двух уровнях сетки

В 0.3.0 добавлен исследовательский режим `RefinedSolver`. Он рассчитывает
трёхмерное нестационарное течение вокруг неподвижных контуров, вытянутых
по периодическому размаху. Сохраняются ограничения низкоскоростной модели:
Re=10⁴…10⁵, физическое M≤0.15. Целевые Re до 10⁸ и M=0.4 ещё не реализованы.
Это кинетическая дискретизация с гидродинамическим пределом; расчёт отдельных
реальных молекул воздуха здесь не выполняется.

## Сетка и время

Крупная декартова сетка охватывает всю область. Прямоугольная мелкая область
охватывает все стенки и выбранный участок следа, а по размаху — весь период.
Мелкий шаг пространства и времени вдвое меньше крупного: два мелких подшага
на один крупный. Вязкости согласованы в общих единицах. Передача состояния,
регуляризация высших мод и локальная поправка потоков описаны в
[REFINEMENT_RU.md](REFINEMENT_RU.md) и [INTERFACE_RU.md](INTERFACE_RU.md).

Все стенки находятся на мелком уровне. От стены до интерфейса нужно минимум
четыре крупные ячейки. Три крупные жидкие строки под интерфейсом участвуют
в предсказании доноров; более глубокая виртуальная область исключена из
физики и интегралов. Виртуальные крупные ячейки под мелкими не добавляют
ни массу жидкости, ни нагрузки. Щели и тонкие элементы должны реально
разрешаться сеткой; наличие импортированного контура этого не гарантирует.

На входе и верхней/нижней границах задан свободный поток U∞, справа —
экстраполяционный выход с историей, по размаху — периодичность. Это не модель
стенок конкретной аэродинамической трубы. Размеры области и отражения
от открытых границ ещё требуют исследования.

## Стенки, силы и контроль

Используется линейное условие Bouzidi с пересечением точного контура.
Силы получаются из фактического обмена импульсом при отражении, без повторного
применения выходной границы. Учитываются только физические мелкие слои;
периодические доноры не добавляют фиктивный размах.

Cl положителен вверх, Cd — по потоку, Cm — на кабрирование относительно
выбранной точки. Нормировки q·c·Lz и q·c²·Lz используют полную хорду сборки.
Каждая запись — среднее двух мелких интервалов внутри крупного шага,
время записи `(step−0.5)·dt_coarse`. Кадр относится к концу шага `step·dt_coarse`.
При разреженной записи истории промежуточные крупные интервалы не усредняются
в одну запись; частоту записи нужно выбирать по исследуемым пульсациям.

Баланс включает измеренные PDF-потоки через внешние границы и обмен со стеной.
Возможная утечка массы интерполяционной стенки выводится отдельно как
`cumulative_wall_mass_exchange_over_initial_mass`. Малый остаток баланса
не доказывает точность непроницаемости стенки. Fallback-связи также считаются.

Явной SGS, пристенной модели и GPU в этом режиме пока нет. В 0.4 добавлена
многопоточность CPU: [настройки и невязки](MESH_RESIDUALS_CPU_RU.md).
`sgs=none` само по себе не означает DNS. Объёмная релаксация — явный
численный параметр `coarse_bulk_relaxation_time`, а не измеренная молекулярная
объёмная вязкость воздуха. При сравнении сеток/шага надо сохранять её
вязкость в общей системе единиц; например, τb=1 при N=16 соответствует
τb=1.5 при N=32 с прежней решёточной скоростью. GUI сохраняет этот параметр
из загруженного проекта; изменяется он в JSON.

## Запуск, поля и продолжение

В окне выберите вкладку «Сгущение», режим двух уровней и размеры мелкой области.
Число ячеек/хорду относится к крупной сетке. Предварительный просмотр
показывает границы сгущения и оценку памяти. Сохранённый проект имеет
отдельный формат, чтобы старый решатель не запустил его молча на крупной сетке.

```text
python -m aerokinetic.cli plan-refined examples/naca0012_refined_re30000_preview.json
python -m aerokinetic.cli run-refined examples/naca0012_refined_re30000_preview.json --output run_refined --animate
python -m aerokinetic.cli resume-refined run_refined
```

Остановка в окне сохраняет оба уровня в синхронизированный момент,
счётчики и всю историю границ. Продолжение сверяет код, версии, геометрию,
параметры и хеш уже записанной истории. Некоммитированные данные после
checkpoint переносятся в `recovery` перед продолжением. Завершённый расчёт
повторно продолжать нельзя; новый случай запускается в отдельную папку.
Состояния прежнего равномерного режима сохраняют свой формат.

Поля скорости, Cp, давления в Па и завихренности показывают реальные
ячейки двух уровней с общей шкалой. Мелкая область обведена пунктиром.
Гладкость контура профиля на рисунке не заменяет разрешение сетки.
NPZ хранит уровни отдельно; совместное сечение построено на одной координате z.
GIF/PNG создаются локально через Pillow, без ffmpeg. Для физических единиц
нужна заданная хорда; секунды и скорость вычисляются из Re, хорды и ISA.

## Ресурсы и предел доказательств

В комплектном примере NACA0012 при 5°, размахе 0.5c и стандартных размерах
области оценка памяти версии 0.4 составляет около 1.64 ГиБ для 32→64, 10.08 ГиБ для
64→128 и 74.42 ГиБ для 128→256 ячеек/хорду. Это оценка с буферами, невязками и запасом,
не измерение на компьютере пользователя. Уменьшать размеры физической области
ради желаемого разрешения без проверки её влияния нельзя.

Проверки реализации и короткое предварительное сопоставление с Ohtake
сохранены в [отчёте](verification_refined_airfoil/REPORT_RU.md).
Точность Cl/Cd/Cm, сходимость по сетке/области/размаху/времени и длительная
статистика пока не установлены. Следующий этап — количественное исследование
этой неопределённости, затем сравнение установившейся статистики с продувками.
