Новый явно выбираемый режим `exterior_regularized_fd_v1` подключён к
Solver и CLI. Прототип7 ноября прошёл в библиотеку с сохранением
физической сетки, геометрии, начального seed и алгоритма столкновений.

Статус остаётся исследовательским; Windows и точность по продувкам

## Запуск

Использовать установленный wheel этой версии или изолированную среду
разработки с закреплёнными зависимостями. Новых сторонних пакетов нет.

```text
python -m aerokinetic.cli plan examples/naca0012_re30000_n32_exterior_down3.json
python -m aerokinetic.cli run examples/naca0012_re30000_n32_exterior_down3.json --output results/exterior3 --animate
```

Для собственного проекта явно переопределить условие:

```text
python -m aerokinetic.cli run project.json --farfield exterior_regularized_fd_v1 --output results/my_case
```

Число потоков задаёт `grid.openmp_threads`. В новых примерах указано2.
Это управление C-ядрами CPU; NumPy-часть внешнего условия имеет собственные
накладные расходы. Наличие двух потоков не означает удвоения скорости.

Режим поддерживает равномерную CPU-сетку и `flow.sgs="none"`. SGS,
GPU и двухуровневая сетка для него отклоняются явно. Действующие ограничения
Re=10⁴…10⁵ и физического M≤0.15 сохраняются. Этот режим не включает
модель высокого Re или расчёт при6млн.

Старый `legacy` остаётся значением по умолчанию. Отклонённый
`characteristic_transport_v1` сохранён для воспроизведения прежних опытов;
он не является новым исправленным условием.

## API

```python
from aerokinetic import Flow, Grid, Section, Solver, naca0012

solver = Solver(
    Section((naca0012(81),)),
    Flow(reynolds=30000, alpha_deg=4, physical_chord_m=0.15, sgs="none"),
    Grid(cells_per_chord=32, upstream_chords=1.5, downstream_chords=6,
         transverse_chords=1.5, span_chords=0.5, memory_limit_gib=2,
         target="cpu", openmp_threads=2,
         farfield="exterior_regularized_fd_v1"),
)
result = solver.run(12, "results/api_case", sample_every=8,
                    frame_every=2400, check_every=128, average_after=6)
```

Это диагностическое разрешение. Увеличение времени или числа потоков
само по себе не устраняет ошибку сетки. ПримерN64 подготовлен отдельно:
`examples/naca0012_re30000_n64_exterior_down6.json`; его полный расчёт
и сеточная сходимость ещё не выполнены.

## Физическая область и сохранения

`solver.plan.shape`, origin, кадры и объёмные невязки относятся к исходным
физическим ячейкам. По одной служебной ячейке с каждой открытой стороны
выделяется дополнительно; её размер и обмен указаны в
`solver.boundary_diagnostics()` и metadata.boundary_model.

Новый режим хранит распределения до столкновения. Его CPU-checkpoint
имеет numerics_revision2, модельный тег и `pdf_stage="pre_collision"`.
Сохраняются обе PDF, начальное поле входящего инварианта, часы и
накопленные диагностические суммы. При несовпадении фазы или модели
загрузка останавливается. Старые revision1 поддерживаются для старых режимов.

```text
python -m aerokinetic.cli resume results/exterior3
python -m aerokinetic.cli continue results/exterior3 --output results/exterior3_next --additional-time 12
```

resume продолжает прерванную точку к прежнему сроку, continue создаёт
новый временной сегмент. Исходные файлы родителя не редактируются.

## Массовый обмен

К history.csv добавлены четыре поля:

| Поле | Смысл |
|---|---|
| wall_mass_exchange_lattice | сумма входящих минус исходящие популяции стенки за шаг |
| wall_mass_exchange_accumulated | сумма стеночного обмена по завершённым шагам |
| exterior_source_mass_lattice | явный массовый источник реконструкции служебного слоя |
| exterior_source_mass_accumulated | накопленная сумма этого источника |

Единицы — решёточная масса. Накопленные суммы продолжаются через
checkpoint и временные сегменты. t_star в CSV относится к середине
интервала силы/стеночного обмена. Накопленная сумма заканчивается на
state_t*=step*dt; внешний источник применяется в конце шага. Для интеграла
по окну использовать разность накопленных сумм на его граничных шагах.

Массовый обмен Bouzidi не предполагается строго нулевым и не вычитается
из диагностики. Замыкание общего баланса не подтверждает непроницаемость
стенки или точность сил. Эти поля не используются как условие
автоматического останова нестационарного течения.

## Платформы и автономность

Linux CPU: установлены локальные wheels без индекса; проверяются холодная
компиляция, расчёт, CSV, GIF, новый процесс и продление с запретом сети.
Версии и hashes записаны в отчёте. Windows/GPU для нового режима здесь
не выполнялись; нового проверенного Windows-EXE эта ветка не объявляет.
Штатные BAT и сценарии подготовки Windows остаются в проекте.
