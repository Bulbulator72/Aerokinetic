# Проверка механизации в установленной 0.5.0

2 ноября 2026 г. Задача пользователя — проверить работу с механизацией
после уточнения потребности Re около 6 млн. Проверка функций выполнена
в доступном диапазоне выпущенного ядра. **Re=6 млн не рассчитывался**:
существующие проверки ядра и GUI его отвергают. Это не замена требуемого
режима низкорейнольдсовым результатом.

План до начала вычислений: [PLAN.json](PLAN.json). Итоги собраны из
выполненных проверок в [CHECKS.json](CHECKS.json), сырые результаты —
[RUN_CHECK.json](RUN_CHECK.json), [GUI_CHECK.json](GUI_CHECK.json).

## Геометрия и постановка

Проверены однощелевой закрылок (два тела), двухщелевой закрылок с
дефлектором (три тела) и Fowler (два тела). Исходная форма NACA0012,
параметр хорды механизации 0.3, отклонение 20°, параметр gap 0.04,
overlap 0. Для дефлектора заданы хорда 0.1, угол 10°, gap 0.04.
Эти параметры относятся к исходной единичной хорде генератора. После
выдвижения и поворота полная опорная хорда сборки вычислена заново.
Параметр gap не подменяет измеренный минимальный просвет.

Координаты подготовлены геометрическими функциями предоставленного
проекта aero2d и сохранены в [inputs](inputs). Его аэродинамические
решатели не запускались; сравнения с другой CFD-программой не выполнялись.
Для подготовки координат применён SciPy из базовой среды, уже доступный
на стенде. Установленный AeroKinetic получает готовые DAT/JSON и не
приобрёл зависимости от SciPy или aero2d. Хеши исходного генератора,
версии и исходные координаты сохранены вместе с fixtures.

Расчёт: Re=10000 по полной хорде сборки, α=4°, физическая полная хорда
1 м, воздух ISA, U∞≈0.1461 м/с, M≈0.000429. Решёточная скорость 0.04.
Точка момента — x=0.25 полной хорды, y=0 от передней кромки. Кинетическое
ядро D3Q27, double, неподвижные стенки Bouzidi, без явной SGS, нулевое
начальное возмущение. Все тела находятся на мелком уровне, по размаху
периодичность 0.25c. Область: 1.5c перед сборкой, 3c после, по 1.5c
сверху и снизу. Два потока CPU, предел памяти в проекте 3 GiB; плановая
оценка двухуровневых случаев около 1.1 GiB.

Массивы и область трёхмерные, но начальное поле здесь однородно вдоль
размаха. Эти проверки с нулевым возмущением не подтверждают развитие
трёхмерной турбулентности или DNS.

Фактически использованы 32/64 ячейки на полную хорду. Для 48/96 проверена
только геометрия, без вычисления течения. Это не исследование сходимости.
Основной однощелевой прогон доведён до tU/c=1, остальные и тесты
продолжения/отражения являются короткими стартовыми расчётами. Старты
и отдельные окна в UI явно содержат реальные времена.

## Что проверялось

- Общая система координат, полная хорда и точка момента, отсутствие
  пересечений, сохранение координат через DAT и Project.
- Твёрдые ячейки каждого тела и отсутствие 8-связных твёрдых перемычек
  через щели; точные минимальные расстояния полигонов и gap/Δx.
- Наличие граничных связей у каждого элемента, попадание каждой активной
  Bouzidi-связи в собственный контур, отдельный подсчёт fallback-связей.
- Нулевая нагрузка от равномерного изотропного давления для каждого
  тела отдельно и для всей сборки. Это независимая верификация учёта
  стенок, не продувка.
- Реальные Cl/Cd/Cm, четыре компоненты невязок и контроль балансов.
  Обмен массой на интерполированной стенке выводится отдельно: хорошее
  замыкание дискретного бюджета не доказывает точность непроницаемости.
- Зеркальная геометрия с α=−4°: Cd сохраняется, Cl и Cm меняют знак.
  Допуск задан заранее 1e−8. Прямой расчёт и остановка/продолжение
  дали побайтно одинаковые соответствующие строки history/residuals.
- Короткие двухуровневые прогоны double/Fowler и отдельный равномерный
  двухэлементный прогон. Экспорт реальных полей, PNG, GIF, CSV и архива.
- Импорт нескольких DAT и загрузка результатов во всём существующем
  интерфейсе: все контуры на изображении, четыре строки невязок,
  исходные project/history/residuals/summary не меняются при просмотре.

Первоначальный помощник проверки ошибочно требовал, чтобы ближайший
отрезок между любой парой тел проходил целиком через жидкость. В
трёхэлементной сборке между основной частью и задним закрылком находится
дефлектор. Проверка исправлена: для такой пары фиксируется промежуточное
тело; каждая непосредственная щель контролируется отдельно. Численные
допуски не менялись. Изменений расчётного ядра для этих проверок не было.

## Воспроизведение

В установленной закреплённой среде, из папки вне исходного пакета:

```text
python tools/check_multielement.py --fixtures <fixtures> --output <новая папка>
python tools/check_multielement_gui.py --checks <папка расчётной проверки> --output <новая папка GUI> --results
```

Использовался Linux x86_64, CPython 3.12, lbmpy/pystencils 1.4, NumPy
2.3.5, Matplotlib 3.10.8; для GUI — локальный Xorg и Tk 9.0.4. Пути
скриптов, исходников и координат записаны с SHA-256. Установленные
runtime-файлы побайтно сверены с ранее выпущенным wheel 0.5.0.
В численном прогоне Python connect/DNS запрещены; кеш JIT создан
отдельно. Для GUI разрешено локальное X11-соединение. Нативная Windows
и GPU этим прогоном не проверялись.

## Практические границы

Подтверждена техническая работа с несколькими телами в названных
конфигурациях. На используемой сетке в непосредственных щелях лишь
примерно 2.45…2.53 ячейки. Тонкие части дефлектора и закрылка также
имеют мало ячеек по толщине. Наличие жидкости в щели не означает
достаточного разрешения струи и пограничных слоёв.

Прогон короткий, область и размах компактны, Cl/Cd/Cm ещё подвержены
стартовым пульсациям. Численная и статистическая сходимость не
установлены; эти средние нельзя использовать как исследовательские
нагрузки или полярные данные. Результаты двух/трёх тел не являются
подтверждённой физической точностью всех типов механизации.

Сопоставления с продувкой для этой точной геометрии не выполнено:
подходящего экспериментального набора в текущем комплекте нет.
Одноэлементные данные NASA при Re=5.95 млн не заменяют такой эталон.
Режим пользователя Re≈6 млн остаётся задачей развития ядра по
[HIGH_RE_6M_RU.md](../HIGH_RE_6M_RU.md).

## Численные итоги этой проверки

Основной двухуровневый прогон выполнил 800 крупных и 1600 мелких шагов.
Максимальный дефект баланса массы на единицу объёма составил
3.49×10⁻¹⁶, импульса — 1.41×10⁻¹³. При этом накопленный обмен массой
через интерполированные стенки составляет около −1.17×10⁻⁴ исходной
массы области: он не замаскирован малым дефектом бюджета. Максимальное
локальное решёточное число Маха в конечном состоянии около 0.107,
отклонение плотности от 1 около 0.00585. Это не значения физического
числа Маха и не оценка погрешности аэродинамических коэффициентов.

В зеркальном тесте на 32 шагах максимальные различия Cl/Cd/Cm с учётом
смены знака оказались примерно 1.03×10⁻¹³ / 3.27×10⁻¹⁴ / 1.50×10⁻¹⁴.
Fallback-связей стенки в проверенных сгущённых случаях не обнаружено.
Короткие double и Fowler выполнили по 32 крупных шага; их tU/c=0.04
подтверждает запуск, а не развитое обтекание. Полная численная проверка
с компиляцией и экспортом заняла на стенде около 867 с; это не оценка
времени исследовательского расчёта на машине пользователя.
