# Батник тестовых расчётов на компьютере пользователя

8 ноября 2026 г. Численное ядро остаётся 0.5.3, SHA его 34 Python-модулей
совпадают с проверенной сборкой предыдущего этапа. Изменены только доставка
и запуск серии. Новые зависимости не добавлены.

Пользователь получает один UTF-8 BAT; идентичная TXT-копия доступна для
браузеров, которые не скачивают BAT. Внутри находятся исходные тексты,
зафиксированные входы и SHA-256, а не EXE, wheel, матрицы или поля.
PowerShell распаковывает их в отдельную AEROKINETIC_TESTS_053/kit.
Wheel ядра собирается локально и устанавливается в отдельный target.
Существующая библиотека и конфигурация компилятора не заменяются.

## Серия пользователя

- NACA0012, Re=30000, α=4°, ISA, физическая хорда 0.15 м, момент о c/4.
- Трёхмерная периодическая модель с размахом 0.5c, без SGS;
  U_lattice=0.04, ν=0.04·N/30000, неизменный seed=31 и возмущение 10⁻⁴.
- Те же сохранённые контуры, внешний FD-слой и выход 6c.
- Последовательные **N32 и N64 до tU/c=12**, фиксированное окно 6…12.
  Частота сил 0.01 tU/c, кадры каждые 3, checkpoint каждый 1 tU/c.
- До восьми потоков по фактическому числу логических CPU; число фиксируется
  в PLAN.json. Применяется остановка по времени без лимита реальных часов.
- Нехватка RAM/диска останавливает запуск и сохраняет диагностику;
  сетка, область, Re и вязкость не уменьшаются.

Сначала выполняется короткая проверка CPU1/несколько потоков, независимых
балансов жидкой маски, стеночного обмена, сил и момента, фазы PDF,
продолжения в новом процессе и принадлежности кадров физической области.
Критерии заранее записаны в
[study_protocol.json](../../tools/research_tests/study_protocol.json).
Контроль N32 с прежним Linux-прогоном — проверка реализации на другой
платформе; это не эксперимент. Критерий среднего/RMS 10⁻⁶ предложен
для этого контроля и не является требованием пользователя к точности.

Эксперимент отдельно: Ohtake, Nakae, Motohashi (2007),
https://doi.org/10.2322/jjsass.55.439, сохранённые Cl/Cd/Cm при Re=30000.
Сравнение и дрейф сохраняются без подгонки параметров. Два разрешения
не устанавливают порядок/GCI; предыдущий разрыв с продувкой не объявляется
исправленным. Режим Re≈6 млн не включён.

Короткий `--smoke` явно обозначен и применяется только разработчиком;
он не заменяет заданную пользователю длинную серию. BAT запускает обычные
N32/N64, а не smoke. Полный предыдущий экспериментальный отчёт 0.5.3
остаётся отдельным и не переписывается новыми короткими результатами.
Первая попытка дополнительного unit-теста OpenMP остановилась при импорте
из-за read-only домашнего кэша среды. Для теста задан отдельный tmp-кэш;
допуски не менялись. Сценарий BAT уже использует частный кэш. Неудачный
лог сохранён в provenance/.

## Остановка и результат

STOP_TESTS.bat создаёт запрос остановки, который ядро проверяет между
шагами. Ожидается безопасное сохранение. Повторный запуск возобновляет
исходный checkpoint, восстанавливает согласованный префикс истории
и пропускает завершённые случаи. Одновременный запуск блокируется ОС.
Изменение параметров активной серии отклоняется.
Блокировка охватывает также локальную подготовку пакетов. Старая команда
остановки снимается перед подготовкой; новая, поступившая во время неё,
сохраняется до запуска ядра. Дополнительный тест проверяет этот случай
и невозможность второго запуска стереть ожидающий запрос.

FOR_REVIEW.zip содержит PLAN/RUNTIME, проекты, CSV, невязки, логи,
короткие проверки, описательную статистику, SVG и последнее сечение
каждого случая. Полные checkpoint остаются на ПК. ZIP и его хеши
создаются локально, автоматической отправки куда-либо нет.

Нужен Python 3.12 x64 из исходной установки. Если есть только старый
замороженный EXE без Python, батник явно сообщает отсутствующий компонент;
автоматическая загрузка и установка системного ПО не выполняются.
Существующий переносимый компилятор используется при его обнаружении;
иначе читается исходная конфигурация pystencils.json.

[Инструкция](../../tools/research_tests/README_RU.md),
[сборщик одного файла](../../tools/research_tests/make_transfer.py).
Сырые текстовые доказательства находятся в raw/, их состав и хеши —
в FILES_SHA256.json. Локальные wheels, NPZ, DLL/SO и ZIP не публикуются
в репозитории; публикуются исходники, текстовые отчёты и их идентификаторы.
