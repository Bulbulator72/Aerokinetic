# Локальное сгущение: первый проверяемый этап

27 октября 2026 г. Реализованы операторы переноса состояния между
трёхмерными уровнями 2:1. Этот документ описывает первый этап — разовый
перенос состояния. Следующим отдельным этапом реализован
[пространственный стык двух жидких областей](INTERFACE_RU.md).
Рабочий решатель профиля и вкладка поля течения сохраняют равномерную сетку;
новое сгущение ещё не подключено к пользовательскому расчёту Cl/Cd/Cm.

Код — [refinement.py](../src/aerokinetic/refinement.py), воспроизводимый
численный эксперимент — [refinement_checks.py](../src/aerokinetic/refinement_checks.py).
Критерии до первого прогона — [PLAN.json](verification_refinement/PLAN.json).
Итоговый отчёт хранится в этой же папке проверки.

## Какой перенос реализован

Уровни используют акустическое масштабирование: мелкая ячейка вдвое
меньше, её шаг времени тоже вдвое меньше. Поэтому решёточная скорость
того же физического течения сохраняется, а вязкость в решёточных единицах
удваивается:

```text
dx_f = dx_c/2; dt_f = dt_c/2
nu_physical = cs² (tau_shear - 1/2) dx²/dt, cs² = 1/3
tau_shear_f = 1/2 + 2 (tau_shear_c - 1/2)
tau_bulk_f  = 1/2 + 2 (tau_bulk_c  - 1/2)
zeta_physical = (2/3) cs² (tau_bulk - 1/2) dx²/dt   [3D]
```

Здесь `zeta` — кинематическая объёмная вязкость, `nu` — сдвиговая;
их параметры не смешиваются. Включение схемы в основной cumulant-решатель
потребует согласовать его объёмную релаксацию отдельно: сейчас она равна
1 на единственном уровне. Численный стенд задаёт её явно на обоих уровнях.
Одинаковый Re сам по себе не проверяет согласованность всех коэффициентов.

Из PDF извлекаются 10 полей: плотность, три компоненты **импульса**
и шесть компонент неравновесного напряжения. Интерполируются плотность
и импульс, а скорость вычисляется как `j/rho`. Усреднение скоростей при
разной плотности не сохраняет импульс.

Для состояния **до столкновения**, без внешней силы:

```text
Pi_neq = sum_i f_i c_i c_i - rho cs² I - j j/rho
Pi_neq_deviatoric_f = [tau_shear_f dt_f / (tau_shear_c dt_c)] Pi_neq_deviatoric_c
Pi_neq_isotropic_f = [tau_bulk_f dt_f / (tau_bulk_c dt_c)] Pi_neq_isotropic_c
```

Это следует из первого члена Chapman–Enskog:
`Pi_neq_deviatoric = -2 rho cs² tau_shear dt S_deviatoric`.
После столкновения коэффициент переноса иной. Основной `Solver` хранит
PDF после столкновения: **передавать его массивы этому API нельзя**.
Конструктор требует явный `pdf_stage="pre_collision"` и отклоняет
`post_collision`. Указание стадии является контрактом вызывающего кода;
определить её по одному массиву чисел невозможно.

На каждой оси используются средние по пяти крупным ячейкам:

```text
delta_i = (11/64) (a[i+1]-a[i-1]) - (3/128) (a[i+2]-a[i-2])
left_child  = a[i] - delta_i
right_child = a[i] + delta_i
```

Последовательное применение по x/y/z даёт восемь дочерних ячеек.
Их среднее совпадает с родительским. Полиномы до четвёртой степени
в каждой координате воспроизводятся для **средних по объёму**.
Обратный перенос усредняет восьмёрку дочерних ячеек. Это сохранение
при замене представления состояния, а не доказательство баланса потоков
при непрерывном обмене между областями.

Для шага `t+dt_c/2` предусмотрена интерполяция тех же 10 полей во времени.
Вызывающий код обязан дать реальные донорские состояния до столкновения
при `t` и `t+dt_c`, корректные halo-слои и синхронизированные часы.
Функция переноса сама не управляет часами и streaming. Этим занимается
отдельный экспериментальный [модуль пространственного стыка](INTERFACE_RU.md).

PDF восстанавливаются из равновесия D3Q27 и второй эрмитовой компоненты
напряжения. Независимые неравновесные моды более высокого порядка
регуляризуются, то есть намеренно отбрасываются. Это не точное сохранение
всех 27 PDF. Неравновесные напряжения усредняются отдельно от `rho` и `j`;
сохранение полного фильтрованного потока `rho*u*u` этим не утверждается.

## Ограничения операторов

- Только гладкие полностью жидкие донорские блоки; **два настоящих
  halo-слоя** со всех сторон. Сам оператор не придумывает внешние данные.
- Порядок направлений stencil передаётся явно; оба способа хранения PDF
  проверены, включая zero-centered. Пространственный шаг изотропный.
- Модель без внешней силы и SGS, локальный решёточный Mach не выше 0.3.
  Этот аварийный предел не подтверждает точность при таком Mach.
- Предиктор не ограничивается по монотонности. Возле резкого изменения
  возможен выброс; неположительная плотность или отрицательные физические
  PDF останавливают перенос. Скрытого clipping или смены вязкости нет.
- Стенки, щели, выходная граница, распределение сил по уровням и
  многоуровневые контрольные состояния не поддержаны.
- NumPy-реализация предназначена для верификации; производительность
  и пиковая память на больших блоках требуют отдельной работы.

## Что проверено на первом этапе

Независимые тесты проверяют суммы физических PDF, а не повторяют формулу
экстрактора. Есть проверки каждого родителя, перестановки stencil,
меняющейся плотности во временной интерполяции, 100 циклов переноса,
неположительных состояний и точных полиномиальных средних. Равновесие
сверяется с настоящим setter закреплённого cumulant-ядра lbmpy 1.4.

В численном опыте вся периодическая область меняет разрешение при
синхронизированном времени. Волна переносится и затухает по известному
аналитическому закону. Отдельный отрицательный контроль намеренно не
масштабирует `tau` на мелком уровне: проверка должна обнаружить вдвое
неверную физическую вязкость.

Исходная проверка дала ошибку комплексной гармоники 0.6223% при
крупной → мелкой → крупной сетке; полный дрейф массы 8.9×10⁻¹⁵.
Эта ошибка относится **к контрольной волне**, не к аэродинамическим
коэффициентам. Наблюдаемый порядок около пяти относится только к
пространственному предиктору гладких средних, не ко всему LBM-решателю.
Результаты установленного пакета и фактические версии см. в отчёте.

## Запуск разработчиком без сети

Существующие закреплённые зависимости достаточны; новых скачиваний нет.
Нужен уже работающий локальный компилятор для первой JIT-компиляции.

```text
python -m pytest tests/test_refinement.py -q
python -m aerokinetic.cli verify-refinement --output refinement_check_01
```

Вторая команда создаёт `checks.json` и `shear_wave.png` в новой папке.
Выполняется задача проверки метода, профиль при этом не рассчитывается.
Для установленного wheel в чистой среде:

```text
python tools/check_refinement_offline.py --output refinement_offline_01
```

Скрипт блокирует Python socket-соединения и DNS, проверяет путь импорта,
создаёт пустые кеши и запускает тесты и численный CLI. Это контроль
обращений Python, а не отключение сети на уровне ОС. В данной среде
проверяется Linux CPU. Windows/MSVC и GPU требуют своего выполнения.

Номер стабильного приложения пока остаётся 0.2.1. Внутренний wheel этого
снимка отличают хеши в отчёте; ранее выданное пользователю стабильное
обновление не заменено. Сгущение ещё не выпущено как возможность GUI.
