# Сборка переносимого AeroKinetic дома

Это **сценарий сборки**, а не уже проверенный Windows EXE. Цель — одна
папка с `AeroKinetic.exe`, интерпретатором, библиотеками и локальным
компилятором, которая переносится на рабочий ПК без установки Visual Studio.

## Что сделать пользователю

1. Дома, на Windows x64 с интернетом, закрой AeroKinetic. Используй папку
   программы, в которой расчёты уже работают, полный Python 3.12 и
   установленный C++ toolchain. Короткий путь вроде `C:\AK` предпочтителен.
2. Для интерфейса 0.5.0 сохрани **`BUILD_AEROKINETIC_UI_050.txt`** как
   **`BUILD_AEROKINETIC_UI_050.bat`** рядом с `6_run_AEROKINETIC.bat`.
   Прежний `BUILD_AEROKINETIC_PORTABLE.txt` содержит комплект 0.4.0.
   Требуется существующая `.venv\Scripts\python.exe`.
3. Запусти этот BAT обычным двойным щелчком. Он скачает закреплённые пакеты
   сборки, создаст отдельную среду и копию инструментов, соберёт программу
   и выполнит короткие расчёты. Оставь окно открытым до итогового кода.
4. При **`BUILD_EXIT_CODE=0`** открой в исходной папке
   **`PORTABLE_READY_TO_COPY.txt`**. В нём указан точный путь готовой папки
   **`dist\AeroKinetic`**. Копируй её **целиком**, включая `_internal` и
   инструкции. Остальные папки сборки переносить не требуется.
5. На рабочем ПК распакуй/скопируй комплект в новую локальную папку,
   отключи сеть и запусти **`CHECK_PORTABLE.bat`**. Дождись
   **`CHECK_EXIT_CODE=0`**. Проверка повторит компиляцию с пустым кешем,
   расчёты, продолжение и экспорт.
6. Запускай программу через **`AeroKinetic.exe`**. На целевом ПК отдельные
   Python/пакеты/Visual Studio по замыслу комплекта не нужны; это должно
   быть подтверждено предыдущим шагом именно на рабочем ПК.

При ошибке сборки пришли **`PORTABLE_BUILD_LAST.log`** из исходной папки.
При ошибке рабочего EXE пришли **`CHECK.json`** и
**`AEROKINETIC_PORTABLE.log`** из самой новой подпапки `checks`.
Не требуется заново запускать Visual Studio Installer на рабочем ПК.

## Что делает сценарий

- Сохраняет работающую программу, её `.venv`, проекты и расчёты.
  Каждый запуск строит новый комплект в `portable_builds\build_…`.
- Использует проверенный wheel AeroKinetic 0.5.0 и сверяет с ним исходники.
  Версии расчётных зависимостей сохранены. PyInstaller закреплён на 6.16.0;
  altgraph 0.17.5 совместим с закреплённым setuptools без `pkg_resources`.
- Копирует x64 MSVC, стандартные заголовки/библиотеки, Windows SDK UM/UCRT,
  CRT/OpenMP DLL и Python SDK из существующей домашней установки.
  Это личный перенос инструментов пользователя между его ПК; комплект
  не заявляется как публичный redistributable компилятора Microsoft.
  Доступные документы лицензий сохраняются.
- Подключает bundled MSVC через адаптер строго для pystencils 1.4:
  системный поиск Visual Studio при запуске EXE отключён. Флаги численного
  ядра сохраняются; глобальный `sysconfig` не переписывается.
- Сохраняет исходники для идентичности checkpoint, метаданные пакетов,
  экспериментальные CSV, GUI и локальные ресурсы. Пишет SHA-256 манифест.
- Переносит комплект в путь с пробелами/кириллицей, удаляет из окружения
  проверки пути разработчика и запускает **замороженное** приложение.
- Проверяет OpenMP, разные сетки, штатную остановку/продолжение с точной
  историей, четыре невязки, встроенные данные, поле, CSV/PNG/GIF, отчёт
  и реальные окна сетки/невязок.

Понадобится несколько гигабайт; в процессе одновременно хранятся исходная
копия инструментов, пакет и его копия для проверки переноса. Размер и
время зависят от домашнего SDK и диска; заранее фиксированного размера нет.
На целевом CPU нужен набор инструкций выбранных флагов (обычно AVX).

Журналы обычного запуска и JIT-кеш находятся в
`%LOCALAPPDATA%\AeroKinetic\portable\…`. Самопроверка создаёт новый
изолированный кеш; обычные повторные запуски используют постоянный кеш
для того же комплекта. Каждая проверка оставляет свои результаты.

## Что пока не доказано

Windows-сборка и запуск на чистом рабочем ПК здесь не выполнены. Локальная
разработка проверяет общую упаковку в Linux отдельно; это не Windows EXE.
Даже успешная домашняя самопроверка с очищенными путями не заменяет
проверку на другом ПК без установленных средств разработки и без сети.
Блокируются соединения/DNS Python; это не системная изоляция всех нативных
библиотек. На целевом ПК сеть отключается отдельно.

Короткие случаи проверяют поставку, а не сходимость сетки и не точность
Cl/Cd/Cm по продувкам. Численная область применимости ядра не расширена.
Комплект предназначен для CPU; CUDA/CuPy в эту сборку не включены.
