# AeroKinetic 0.5.1 — воспроизводимость и продолжение расчётов

7 ноября 2026 года. Исследовательский выпуск; зависимости runtime прежние.
[Подробный отчёт и сырые данные](verification_stage1_20261106/REPORT_RU.md).

## Изменения

- Точка момента больше не меняет начальное возмущение потока. Сохранённый
  checkpoint восстанавливается со своим прежним полем.
- Устранён лишний шаг при погрешности деления длительности на шаг времени.
  Единый расчёт числа шагов используется в обоих решателях и индикаторе GUI.
- Завершённый или штатно остановленный CPU-результат можно продлить в
  новую папку через CLI/API. Равномерная и двухуровневая сетки поддержаны.
- Сборщик EXE выбирает wheel текущей версии, проверяет его соответствие
  исходникам и включает все модули API/CLI. Самопроверка проверяет хеши
  полного runtime. Старые автономные установщики обновлены с 0.4.0 на 0.5.1.

## Продление через CLI

Для среды с установленной библиотекой 0.5.1:

```text
python -m aerokinetic.cli continue runs/parent --output runs/continued --additional-time 18 --average-after 12
```

Если родитель дошёл до tU/c=6, цель нового отрезка будет tU/c=24.
`--additional-time` — добавляемое время tU/c; `--average-after` — глобальное
время начала осреднения. Без последнего параметра осреднение начинается
не раньше начала нового отрезка и прежнего порога. Новая папка должна быть
пустой и находиться вне родительской. Re, геометрию и сетку команда сохраняет.

`history.csv` содержит только новые отсчёты; прежняя история остаётся в
родительской папке. Новый `continuation.json` связывает отрезки и хранит
хеши исходных файлов. `summary.json` осредняет только новый отрезок.
При объединении историй необходимо учитывать различия частоты записи.

После остановки дочернего отрезка его можно возобновить обычной командой:

```text
python -m aerokinetic.cli resume runs/continued
```

`resume` сохраняет уже заданную цель и не удлиняет завершённый расчёт.
Условия окончания сохраняются: например, заданный лимит шагов может
завершить отрезок раньше длительности. Обычная остановка сохраняет checkpoint.

API:

```python
from aerokinetic import continue_run

summary = continue_run("runs/parent", "runs/continued", 18, average_after=12)
```

В GUI сохраняется прежнее возобновление остановленного расчёта.
Кнопка продления завершённого расчёта ещё не добавлена. Переносимый EXE
открывает GUI; пример CLI выше требует установленной Python-библиотеки.

## Как подготовить новую переносимую папку Windows

Использовать **один файл**
[BUILD_AEROKINETIC_UI_051.txt](../distribution/BUILD_AEROKINETIC_UI_051.txt).
Сохранить целиком как `BUILD_AEROKINETIC_UI_051.bat` в существующую домашнюю
папку AeroKinetic рядом с `6_run_AEROKINETIC.bat` и `.venv`.

Закрыть программу, запустить этот BAT дома на Windows с интернетом и
работающим C++-компилятором. Он создаёт отдельную среду, собирает новую
программу и проверяет её после переноса в папку с пробелами и кириллицей.
Прежняя `.venv` и прежний EXE не обновляются этим сценарием.
Путь готовой папки записывается в `PORTABLE_READY_TO_COPY.txt`.

На рабочий компьютер переносится **вся указанная папка**. Там запустить
`CHECK_PORTABLE.bat` с отключённой сетью и дождаться результата проверки,
затем `AeroKinetic.exe`. Visual Studio Installer на целевом ПК этим сценарием
не запускается: используется личная копия compiler/SDK внутри комплекта.

TXT содержит код и wheel, а не готовый Windows EXE и не все установочные
зависимости. Интернет нужен на этапе домашней сборки. Новую Windows-сборку
здесь выполнить нельзя: текущая проверка проходит на Linux. Результат
проверки Windows/MSVC и конкретного офлайн-ПК остаётся отдельным.

Файлы сборки 0.5.0 сохранены как история. Для этого выпуска выбирать
только имя с **051**. Контрольные суммы — в соседнем `.check.json`.

## Научный статус

Контрольный расчёт установленного 0.5.1: NACA0012, Re=30000, α=4°,
N32, tU/c=12, осреднение 6…12. Получены Cl≈0.092435, Cd≈0.075839,
Cm(c/4)≈+0.019700. Интерполяция продувки Ohtake при том же Re и α:
Cl≈0.308739, Cd≈0.044509, Cm≈−0.020533. Сетка грубая, границы и статистика
не сошлись; это предварительное сопоставление, не подтверждённая точность.

Исправление воспроизводимости почти не изменило средние этого случая.
Длительный старый расчёт и отдельные тесты выявили влияние внешней области
и сильное отражение линейной волны от поперечного UBB. Следующая научная
задача — проверенное дальнее граничное условие и контроль параметров
переноса перед исследованием сходимости.

Поддерживаемый диапазон ядра остаётся **Re=10⁴…10⁵, Mphysical≤0.15**.
Re≈6 млн, проверенная механизация высокого Re, пристенная модель и GPU
со сгущением ещё требуют разработки. Этот выпуск их не добавляет.
