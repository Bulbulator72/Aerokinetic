# BAT 2: окно установщика закрывается, остаётся только пауза

Пользователь подтвердил: на рабочем ПК нет сети, папка
`downloads/vs_buildtools` занимает несколько гигабайт, окно установщика
появляется и закрывается. Старый BAT 2 после запуска сохранял `%ERRORLEVEL%`,
но показывал результат только при коде 3010. Поэтому по одной надписи
«Для продолжения нажмите любую клавишу» определить исход невозможно.
Это недочёт скрипта; причины конкретного сбоя ещё требуют кода/журнала.

Позже пользователь получил **5003**. По Microsoft это `Bootstrapper failed
to download installer`: сбой получения самого Visual Studio Installer до
установки C++-компонентов. Причину этого сбоя (локальный комплект, чтение,
доверие подписи, другое) один код не устанавливает. Требуется журнал
`dd_bootstrapper*.log` соответствующего запуска.

Полученное фото журнала уточнило сбой: `vs_installer.opc` найден, далее
`InvalidCertificate` и `0x80131509: Signature verification failed`.
Автономная процедура установки сертификатов Microsoft описана в
[отдельной инструкции](COMPILER_CERTIFICATES_RU.md). Устранение на рабочем
ПК пока не подтверждено; дополнительные параметры командной строки сами
по себе не исправляют отсутствующее доверие к сертификатам.

## Что исправлено

- В команде установки `--lang en-US` заменён на документированный параметр
  **`--addProductLang en-US`**. `--lang` относится к подготовке `--layout`.
  В BAT 1b, создающем layout, `--lang en-US` остаётся правильным.
- Сохранён `--noWeb`, запрещающий загрузку отсутствующих продуктовых пакетов.
  Наличие нескольких гигабайт само по себе не доказывает полноту layout.
- Добавлен явный локальный `--channelUri` на `ChannelManifest.json` из
  того же layout, как в инструкции Microsoft для offline-установки.
  До запуска проверяется наличие файла. Это поддерживаемая настройка
  локального источника, а не подтверждённое устранение пользовательского
  5003: результат на его ПК пока неизвестен.
- Пути заключены в кавычки; `start "" /wait` и `--wait` дожидаются bootstrapper.
- До запуска проверяются права администратора и базовые файлы layout.
- Сразу после запуска сохраняется и **всегда выводится** `INSTALL_EXIT_CODE`.
  Команды сбора журналов не меняют возвращаемый исход установки.
- Сводка — `downloads/compiler_install.log`, до восьми последних журналов
  Microsoft из TEMP — в новой подпапке `downloads/compiler_install_details`.
  Эти журналы могут относиться и к предыдущему запуску; их время нужно
  сопоставлять с текущим запуском. Отсутствие журналов показывается отдельно.

## Как исправить прямо на рабочем ПК без загрузки нового файла

1. Открыть `2_install_COMPILER_OFFLINE.bat` в Блокноте.
2. В строке `start ...` заменить **`--lang en-US`** на
   **`--addProductLang en-US`**.
3. Сразу после `set "AEROKINETIC_RESULT=%ERRORLEVEL%"` добавить:

```bat
echo INSTALL_EXIT_CODE=%AEROKINETIC_RESULT%
```

4. Сохранить BAT, запустить от администратора и записать код перед паузой.
   В исходном BAT переменная называется `AEROKINETIC_RESULT`; в полной
   исправленной версии — `AEROKINETIC_INSTALL_RESULT`. Для ручной правки
   старого файла использовать исходное имя, указанное выше.

Полная версия доступна как `2_install_COMPILER_OFFLINE_FIXED.txt`. Сохранить
весь текст как `2_install_COMPILER_OFFLINE_FIXED.bat` рядом с исходным BAT 2
и запустить от администратора. Это самостоятельный BAT, которому нужны
уже перенесённые `downloads/vs_buildtools`. Интернет и новые Python-пакеты
не требуются. Он не устанавливает сертификаты, не меняет сетевые политики
или правила антивируса, не отключает проверку подписей.

Для ручной правки после кода 5003: сначала убедиться, что в
`downloads\vs_buildtools` есть `ChannelManifest.json`. В строку `start ...`
существующего BAT сразу после `--noWeb` добавить:

```bat
--channelUri "%~dp0downloads\vs_buildtools\ChannelManifest.json"
```

Остальные параметры и вывод кода сохранить. Если файла нет, восстановить
его из того же полного домашнего layout. Не скачивать отдельно манифест
произвольной версии. Повторный 5003 требует чтения Microsoft bootstrapper
лога, а не дальнейшего случайного изменения параметров.

## Значения кодов по документации Microsoft

| Код | Значение |
|---|---|
| 0 | Установщик сообщил успех; дальше выполнить проверки программы |
| 3010 | Успех; перед использованием требуется перезагрузка |
| 740 | Требуются повышенные права; в BAT также обозначает сбой их проверки |
| 1001 | Уже выполняется Visual Studio Installer |
| 1618 | Выполняется другая установка |
| 5003 | Bootstrapper не смог получить установщик; причины смотреть в журнале |
| 5005 | Ошибка разбора параметров bootstrapper |

Код 2 в этом BAT означает отсутствие базовых файлов layout и выставляется
самим BAT до запуска Microsoft bootstrapper. Не интерпретировать его как
код последнего. Код 0 не заменяет фактическую проверку компиляции:
после установки запускаются `FIX_COMPILER_WINDOWS.bat` и/или BAT 3.
Аналогично, код 3 выставляется BAT при отсутствии локального
`ChannelManifest.json`, до запуска Microsoft bootstrapper.

## Основание и проверки

Документация получена через Firecrawl 27 октября 2026 г., вариант VS 2022:

- https://learn.microsoft.com/en-us/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=vs-2022
- https://learn.microsoft.com/en-us/visualstudio/install/create-an-offline-installation-of-visual-studio?view=vs-2022
- https://learn.microsoft.com/en-us/troubleshoot/developer/visualstudio/installation/set-up-vs-professional-2022-offline-machine
- https://learn.microsoft.com/en-us/visualstudio/install/deploy-a-layout-onto-a-client-machine?view=vs-2022

Отдельно проверяются ASCII/CRLF, идентичность TXT и BAT, обязательный
`--noWeb`, правильный параметр языка, немедленное сохранение кода,
безусловный его вывод до `pause` и независимость от последующего сбора логов.
Windows/CMD/PowerShell в текущей Linux-среде не запускались: `not_run`.
Причина закрытия окна на пользовательском ПК остаётся `inconclusive`
до получения подробностей журнала; код 5003 уже получен. Расчётное ядро
не менялось.
