# Переносимый комплект Windows: состав и условия готовности

29 октября 2026 г. Основание — запрос пользователя на `.exe` со всеми
необходимыми папками для запуска на компьютере без интернета.

Подготовлен [сценарий домашней сборки](BUILD_PORTABLE_RU.md).
Обновление интерфейса 0.5.0 описано в [RELEASE_050_RU.md](RELEASE_050_RU.md).
Его реализация проверяется отдельно; нативная Windows-сборка и проверка
на рабочем ПК остаются необходимыми этапами. Старое техническое основание
ниже сохраняется.

Статус: сценарий сборки реализован; общая упаковка, реальные расчёты и GUI
проверены в Linux. Готовый Windows EXE здесь не собран и не проверен.
Текущая среда разработки — Linux x86_64. Подробные результаты —
[в отчёте](verification_portable/REPORT_RU.md). Для первого запуска сборщика
дома используй [пошаговую инструкцию](BUILD_PORTABLE_RU.md).

## Формат поставки

Предпочтительный вариант — одна переносимая папка **AeroKinetic**, в ней
**AeroKinetic.exe** и все необходимые runtime-компоненты. Пользователь
копирует целую папку на локальный диск и запускает EXE. Отдельная установка
Python, Python-пакетов и Visual Studio на рабочем ПК не входит в целевой
пользовательский сценарий. Для достижения этого нужно включить либо
устранить зависимость от локального toolchain и проверить её отдельно.

Режим PyInstaller `onedir` соответствует этому формату. Его проще
диагностировать и обновлять; библиотеки не извлекаются заново во временную
папку при каждом запуске, как в `onefile`. Один физический EXE с внутренней
распаковкой можно рассматривать после проверки переносимой папки.

## Что нужно упаковать

| Компонент | Особенность существующего проекта |
|---|---|
| Python x64 и расширения | Версия и ABI согласованы с закреплёнными пакетами |
| Интерфейс и графика | Tcl/Tk текущей версии либо runtime выбранной новой оболочки, Matplotlib, Pillow, локальные ресурсы |
| Расчётные зависимости | NumPy, lbmpy 1.4, pystencils 1.4, SymPy и транзитивные зависимости |
| Локальная компиляция | Совместимый C/C++ toolchain, заголовки/библиотека Python, системные SDK и необходимые runtime DLL |
| Данные | Встроенные экспериментальные CSV/метаданные, примеры, лицензии и документация |
| Совместимость | Метаданные версий пакетов и файлы, по которым проверяется численная идентичность checkpoint |
| Записываемые данные | Отдельные доступные для записи папки проектов, результатов, журналов и JIT-кеша |

Состав и лицензии конкретного компилятора/SDK устанавливаются при реализации
поставки. Наличие домашнего установленного MSVC ещё не доказывает, что
его можно переносить как готовый автономный runtime без подготовки и проверки.

## Существенные особенности, найденные в коде

1. В закреплённом pystencils 1.4 импорт CPU JIT читает конфигурацию MSVC,
   а `.compile()` генерирует C++ и вызывает `cl.exe`/`link.exe` на Windows.
   Компиляция зависит от выбранного случая; готового GUI EXE недостаточно.
2. `pystencils.cpu.cpujit.compile_module()` использует `sysconfig` для
   `Python.h` и `python312.lib`. В замороженной программе эти пути должны
   указывать на включённые файлы, а не на домашнюю установку Python.
3. `pystencils.include.get_pystencils_include_path()` обращается к реальным
   заголовкам на диске. Их нужно включить как данные сборки.
4. `refined_checkpoint.numerical_identity()` хеширует исходные файлы ядра.
   Упаковка должна сохранить доступ к точным файлам/их проверяемой
   идентичности, не отключая защиту продолжения расчёта.
5. Checkpoint использует `importlib.metadata.version`; соответствующие
   метаданные пакетов должны присутствовать в комплекте.

Текущая ошибка 5003 относится к bootstrapper Visual Studio. Упаковка
интерфейса сама по себе не является исправлением этой ошибки. Цель
переносимого варианта — убрать установку Visual Studio из рабочего сценария,
а не перенести ту же неудачную установку внутрь нового EXE.

## План реализации и проверки

1. Зафиксировать оболочку и точные версии сборщика/runtime, состав
   toolchain и SDK; сохранить источники, лицензии и SHA-256.
2. Выполнить Windows x64 сборку: включить реальные ресурсы, динамические
   импорты, заголовки, метаданные и доступные для записи каталоги.
3. На Windows без установленного Python и Visual Studio отключить сеть и
   очистить расчётный кеш. Проверить запуск интерфейса и первую компиляцию.
4. Выполнить короткий реальный расчёт, затем другой случай/сетку, чтобы
   готовый кеш одного случая не скрывал отсутствие компилятора.
5. Проверить многопоточный CPU, сохранение/продолжение, CSV/PNG/GIF,
   открытие прежних проектов и результатов, кириллицу/пробелы в путях.
6. Сравнить входы и результаты с той же версией установленного ядра;
   сохранить измерения ресурсов и отчёт Windows. Это проверка упаковки,
   а не новая аэродинамическая валидация.

Проверка только открытия окна недостаточна для заявления об автономности
расчёта. Linux-проверки и скачанные Windows-wheels не заменяют этот протокол.

## Источник по сборщику

[Официальная документация PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html)
описывает `onedir`, `onefile`, включение интерпретатора, дополнительные
ресурсы и зависимость сборки от ОС/Python/разрядности. Стандартная сборка
Windows выполняется в Windows-среде; успешное чтение этой документации
не означает, что сборка AeroKinetic уже выполнена.
