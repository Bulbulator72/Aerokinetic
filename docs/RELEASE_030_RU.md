# AeroKinetic 0.3.0: профиль на сгущённой сетке

Новый режим добавляет два одновременно работающих уровня 2:1, мелкую сетку
у неподвижного профиля, Cl/Cd/Cm за оба подшага, реальные поля скорости,
давления и завихренности, GIF и сохранение/продолжение обоих уровней.
В окне появилась вкладка «Сгущение». Прежний равномерный режим сохраняется.

## Обновление без интернета

Нужен **один файл `UPDATE_AEROKINETIC_030.txt`**. Сохраните его целиком как
`UPDATE_AEROKINETIC_030.bat` в папку действующей программы, рядом с
`6_run_AEROKINETIC.bat` и `.venv`. Закройте программу и запустите BAT.
После завершения откройте `6_run_AEROKINETIC.bat`: в заголовке будет 0.3.0.

Файл содержит обновление внутри; отдельно скачивать ZIP или Python-пакеты
не нужно. Поддерживаются установки 0.2.0/0.2.1/0.3.0 с прежними закреплёнными
зависимостями. BAT проверяет SHA-256, создаёт резервную копию в `updates`,
обновляет только приложение/его исходники и добавляет wheel в уже подготовленные
локальные wheelhouse. Пользовательские проекты и расчёты сохраняются.
При ошибке установки предусмотрен откат из резервной копии.

Это обновление не устанавливает и не исправляет Visual Studio Build Tools.
Компьютеру с неработающим компилятором всё ещё нужна отдельная подготовка
его автономного установщика. Код 5003 не связан с выбором сетки.

## Первый запуск

Откройте проект `examples/naca0012_refined_re30000_preview.json`.
Это NACA0012, Re=30000, 5°, хорда 0.15 м, 32 крупные и 64 мелкие
ячейки/хорду, короткое время tU/c=0.2. После проверки ресурсов начните
расчёт в новой папке. Во вкладке «Поле течения» видны два уровня, во вкладке
«Средние» — статистика сохранённой истории.

Для увеличения разрешения меняйте число **крупных** ячеек/хорду во вкладке
«Сетка и время» и проверяйте память. В новом режиме пока нужен один поток
CPU и «Без явной SGS». Работа на GPU ещё не поддержана.
Подробности — [REFINED_AIRFOIL_RU.md](REFINED_AIRFOIL_RU.md).

## Границы результата

Реализован следующий этап алгоритма; аэродинамическая точность ещё не
подтверждена. Короткий пример содержит запусковой процесс и не является
полярой. Пульсации Cl нельзя считать физическими без проверки разрешения,
границ, размаха и статистики. Рабочий диапазон остаётся Re=10⁴…10⁵,
физическое M≤0.15. Утечка массы Bouzidi учитывается отдельно.

Проверки реализации, автономной Linux CPU установки и окна, а также
ограничения экспериментального сопоставления перечислены в
[отчёте третьего этапа](verification_refined_airfoil/REPORT_RU.md).
Запуск Windows/MSVC и GPU в среде разработки не выполнялся.
