# Повторная подготовка дома после 5003 и InvalidCertificate

Обновление 28 октября 2026 г.: пользователь снова сообщил 5003 после
повторных попыток. Точная причина последней попытки пока не установлена.
Перед следующей переустановкой следует собрать
[свежий диагностический отчёт](COMPILER_5003_DIAGNOSTICS_RU.md).
Приведённая ниже подготовка сертификата не является подтверждённым
исправлением последнего сбоя.

Пользователь сообщил, что импорт трёх корневых сертификатов из layout не
устранил код 5003. Новый подробный журнал после импорта ещё не получен:
неизвестно, остался ли `InvalidCertificate` или возник другой сбой.
Повторное скачивание не гарантирует устранения доверия к подписи на другом ПК.

## Что подготовлено

Обновлён BAT 1b: после загрузки и Microsoft `--verify` выполняется четвёртый
этап — загрузка **Microsoft Windows Code Signing PCA 2024** с официального
PKI-узла Microsoft. Этот промежуточный сертификат отдельно рекомендован
Microsoft для поддержания актуальности автономных машин.

Файл сохраняется в layout:

```text
downloads\vs_buildtools\ExtraCertificates\Intermediate\MicrosoftWindowsCodeSigningPCA2024.cer
```

Проверяется точный SHA-256 опубликованного сертификата:

```text
fe229efc927f6d77b738896752a21803a59736baa17bf5be9a50c72e219cbcd2
```

Проверенная копия получена по HTTPS с Microsoft 27 октября 2026 г., 1729
байт DER. OpenSSL показывает Subject `Microsoft Windows Code Signing PCA 2024`,
Issuer `Microsoft Root Certificate Authority 2010`, CA:TRUE, период
08.08.2024–23.06.2035. Это инспекция файла и его происхождения; сертификат
не импортировался в какое-либо системное хранилище в этой среде.

BAT только скачивает файл и сверяет его; он не меняет доверенные сертификаты
домашнего или рабочего ПК. В случае изменения сертификата на стороне
Microsoft несовпадение отпечатка останавливает этот этап для повторной проверки.

## Порядок действий

1. На работе сохранить свежий `dd_bootstrapper*.log` из `%TEMP%` после
   последней попытки установки. Сохранить старый комплект как диагностическую
   копию; исходные проекты и расчёты остаются в своих папках.
2. Дома создать отдельную короткую папку, например **`C:\AK_PREP`**.
3. Сохранить обновлённый `1b_download_COMPILER_ONLINE_FIXED.txt` как
   `1b_download_COMPILER_ONLINE.bat` в новую папку. BAT самостоятельный:
   для подготовки компилятора не требует других файлов проекта или Python.
4. Запустить от администратора с интернетом. Дождаться **всех четырёх этапов**
   и итогового `SUCCESS`. Одного окончания скачивания недостаточно.
5. Перенести **всю новую папку `downloads\vs_buildtools`**, включая метаданные,
   `Certificates`, `ExtraCertificates` и пакеты. На рабочем ПК использовать
   её как единый комплект; старую папку переименовать для сохранения, а не
   смешивать пакеты разных подготовок.
6. На работе для нового `MicrosoftWindowsCodeSigningPCA2024.cer` выполнить
   «Установить сертификат» → «Локальный компьютер» → выбранное хранилище
   **«Промежуточные центры сертификации»**.
7. Повторить BAT 2 от администратора, затем при успехе — BAT 3 и BAT 6.
   При повторном 5003 анализировать свежий подробный журнал.

Успешный Microsoft `--verify` на домашнем ПК подтверждает проверку layout
в той среде, но не состояние хранилищ доверия рабочей Windows. Аналогично,
добавление PCA 2024 является документированной подготовкой, а не доказанным
устранением конкретного сбоя пользователя.
