# Компилятор на отдельном рабочем компьютере

На снимке 27 октября первая ошибка — `ValueError: Visual Studio not found.
Write path to VS folder in pystencils config`. Затем в том же процессе
pytest появляются ошибки частично инициализированного `pystencils.astnodes`.
Сначала требуется устранить обнаружение/установку C++ на этом компьютере.
Наличие установленного Python и открывшегося GUI не подтверждает доступность
компилятора для локальной JIT-компиляции.

`pystencils 1.4` по умолчанию ищет старые переменные `VSxx0COMNTOOLS`, затем
папки Visual Studio в двух стандартных расположениях. Для нестандартной
установки нужен явный путь. Вариант `msvc_version=setuptools` здесь не
используется: в закреплённом setuptools 84 отсутствует старая функция
`msvc14_get_vc_env`, на которую ссылается pystencils 1.4.

## Исправление без интернета

1. Закрыть программу. Сохранить **весь** `FIX_COMPILER_WINDOWS.txt` как
   `FIX_COMPILER_WINDOWS.bat` в папку программы рядом с `.venv` и BAT запуска.
2. Запустить. Скрипт ищет установленный x64 MSVC через `vswhere`, известные
   переменные среды и стандартные папки. Папка скачанного layout не считается
   установленным компилятором: нужны `vcvarsall.bat` и `cl.exe`.
3. При обнаружении скрипт в свежем процессе проверяет импорт pystencils,
   компиляцию/линковку и выполнение маленького ядра `dst=2*src`.
   Только после успеха сохраняет локальный `pystencils.json` и добавляет его
   выбор в существующие BAT 3/4/6. Версия приложения и его зависимости прежние.
   Резервные копии — `compiler_fix_backups`, журнал — `COMPILER_CHECK.log`.
4. Если инструменты не найдены, запустить **на этом ПК**
   `2_install_COMPILER_OFFLINE.bat` от администратора, дождаться установки,
   перезагрузиться при запросе и повторить исправление. `1b` скачивает
   установочный комплект; `2` устанавливает его. Если `downloads/vs_buildtools`
   не был перенесён, сначала подготовить и перенести полный layout.
5. После `PASS` закрыть старые окна программы и командной строки, повторить
   `3_install_WINDOWS_OFFLINE.bat`, затем запустить `6_run_AEROKINETIC.bat`.

Утилита также доступна из исходников:

```text
.venv\Scripts\python.exe tools\configure_windows_compiler.py --root . --vs-path "D:\VS Build Tools"
```

Права администратора не нужны для настройки программы; установка самого
Visual Studio Build Tools может их требовать. Исправление не скачивает
компоненты, не меняет расчётное ядро, Re, сетку, SGS, историю или проекты.
Установленный на домашнем ПК компилятор не переносится копированием `.venv`.

## Критерии проверки до исполнения

- Искать зарегистрированную нестандартную установку, включая пробелы и
  кириллицу в пути; не принимать один установщик за готовый компилятор.
- Сохранять существующие Windows-флаги, версии и аргументы запуска.
- При неудаче компиляции сохранять прежние конфигурацию и BAT побайтно.
- Перед изменениями выполнять настоящий тест JIT, проверяя `dst=2*src`
  точно для 32 целых чисел, представимых в double.
- Проверить текстовый перенос с CRLF и LF и SHA-256 декодированного кода.
- Отдельно фиксировать проверку логики на Linux и реальное выполнение MSVC
  на Windows. Последнее в этой среде остаётся `not_run`.

Настройка компилятора не подтверждает аэродинамическую точность. После неё
требуются обычные численные проверки установленной программы на Windows.
