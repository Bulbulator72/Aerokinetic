# AeroKinetic 0.5.0: самостоятельная программа

Разделы слева: **Геометрия → Сетка → Расчёт → Результаты**. Можно
возвращаться между ними без потери введённых значений. В «Результатах»
форма скрывается и освобождает место графикам. Нижние кнопки запуска,
продолжения и остановки всегда доступны. Для переносимого запуска через
`AeroKinetic.exe` используйте [инструкцию 0.5](docs/RELEASE_050_RU.md).

Название проекта и отметка несохранённых изменений видны сверху.
Ctrl+O открывает проект, Ctrl+S сохраняет, Ctrl+Shift+S — сохраняет как,
Ctrl+N создаёт новый. В числовых полях допустимы запятая, точка и `1e4`;
пустые значения, NaN/Inf и дробное число потоков отвергаются с указанием
поля. Ошибочный ввод сохраняется для исправления.

Новые кнопки: **«Сеткопостроитель…»** и **«Невязки / остановка…»**.
В сетке теперь можно выбрать несколько потоков CPU для двух уровней.
[Автономное обновление 0.4](docs/RELEASE_040_RU.md),
[определение невязок и условий окончания](docs/MESH_RESIDUALS_CPU_RU.md).

Для установленной 0.2.0/0.2.1/0.3.0 подготовлено [автономное обновление](docs/RELEASE_040_RU.md).
Оно добавляет расчёт профиля на двух уровнях сетки; вкладка «Средние» сохраняется.

Запуск Windows: **`6_run_AEROKINETIC.bat`** после автономной установки.
Программа работает локально, без браузера и программы Claude.

Это исследовательская версия с прежним трёхмерным низкоскоростным ядром:
Re=10⁴…10⁵, физическое M≤0.15. Точность Cl/Cd/Cm по продувкам пока
не подтверждена. Целевые Re до 10⁸ и M до 0.4, сжимаемая модель,
полная валидация сгущённой сетки и пристенная модель остаются следующими этапами.

В разделе **«Сетка»** выберите «Два уровня 2:1». В этом разделе
число ячеек теперь относится к **крупной** сетке: 64 означает 128 у профиля.
Мелкая область охватывает профиль и выбранный участок следа; её размеры
задаются в группе «Область мелкой сетки». Кнопка «Обновить сетку» показывает
её пунктиром и оценивает память до расчёта.

Потоки CPU, время, частоты записи и подсеточная модель находятся в разделе
«Расчёт». Кнопка «Невязки и стоп» открывает четыре компоненты, их историю и
условия окончания. У графиков есть панель увеличения, перемещения и
сохранения изображения. Шкала поля автоматическая для каждого кадра;
пиксели сохраняют фактическое разрешение данных без сглаживания.

Новый режим работает на CPU с выбранным числом потоков, без явной SGS. Старый
равномерный режим доступен отдельно. Короткий пример для запуска:
`examples/naca0012_refined_re30000_preview.json` — откройте как проект.
Его 64 мелких ячейки/хорду и tU/c=0.2 не являются достаточным разрешением
и временем для исследовательских выводов. Подробнее —
[постановка на двух уровнях](docs/REFINED_AIRFOIL_RU.md).

## Подготовка и установка Windows

Нужны Windows x64, полный CPython 3.12 с Tcl/Tk и C++ Build Tools.
В комплект входят Python-wheels с проверяемым SHA-256. Python и компилятор
при их отсутствии подготавливаются на машине с интернетом:

1. `1_download_ONLINE_WINDOWS.bat` — Python и Python-пакеты.
2. `1b_download_COMPILER_ONLINE.bat` — автономный layout компилятора,
   если C++ Build Tools ещё не установлены; требуется несколько гигабайт.
   Запускать от имени администратора. Папку программы удобно разместить
   в `C:\AK`: полный путь `downloads\vs_buildtools` должен быть короче
   80 символов. BAT показывает этапы и прогресс, записывает ошибки в
   `downloads\compiler_download.log` и проверяет готовый layout через
   Microsoft `--verify`.
3. Перенести всю папку программы, включая `downloads`, на рабочую машину.
4. При необходимости: `0_install_PYTHON_OFFLINE.bat`,
   `2_install_COMPILER_OFFLINE.bat`; затем `3_install_WINDOWS_OFFLINE.bat`.
5. Запускать `6_run_AEROKINETIC.bat`.

Полный Python включает Tcl/Tk по умолчанию; при выборочной установке этот
компонент должен быть включён. Первичная компиляция ядра выполняется
локально. Пакеты не скачиваются во время работы программы.
При первой ошибке `Visual Studio not found` см.
[проверку и настройку обнаружения компилятора](docs/COMPILER_DISCOVERY_FIX_RU.md).
Если окно BAT 2 быстро закрывается, а консоль показывает только паузу, см.
[исправление параметров и вывод кода установки](docs/COMPILER_INSTALL_FIX_RU.md).
При `InvalidCertificate` для `vs_installer.opc` см.
[сертификаты для автономной установки](docs/COMPILER_CERTIFICATES_RU.md).
Ошибки `pystencils.astnodes` после такого сбоя могут быть следствием
частично выполненного импорта в том же процессе.

## Работа с проектом

- Выбрать четырёхзначный NACA или загрузить контуры DAT. Несколько DAT
  должны задавать элементы в общей системе координат. Окно умеет считать
  импортированную механизацию; её встроенный генератор ещё разрабатывается.
- Задать Re по полной хорде сборки, угол и физическую полную хорду в метрах.
  Скорость и M вычисляются по ISA. Точка момента задаётся в метрах
  относительно передней кромки, в осях исходной геометрии.
- «Показать профиль и оценить ресурсы» показывает геометрию при выбранном
  угле, число ячеек и оценку памяти. Это оценка, а не измерение пика RAM.
- «Сохранить проект» создаёт JSON со всеми координатами. Исходные DAT
  для повторного открытия этого JSON больше не нужны.
- «Начать расчёт» создаёт новую отдельную папку внутри выбранной папки.
  Значения по умолчанию предназначены для короткой проверки запуска.

Сетка по умолчанию грубая, длительность короткая. Средние стартового
участка нельзя принимать за установившуюся поляру. Для исследований
необходимы сходимость сетки/области/размаха/шага, достаточные разгон и
статистика, согласование с условиями продувки.

## Остановка и продолжение

«Остановить и сохранить состояние» завершает текущий шаг и записывает
`checkpoint.npz`, историю, кадр и сводку. Во время компиляции остановка
выполнится после подготовки ядра. «Продолжить из папки» восстанавливает
исходный проект и продолжает до первоначально заданного конечного времени.
Параметры остановленного расчёта при продолжении не меняются.

Периодичность контрольных состояний задаётся в шагах; `0` отключает
периодические записи, но сохраняет состояние при штатной остановке и
завершении. При аварии можно продолжить с последнего законченного
контрольного состояния. До первой такой записи расчёт запускают заново.
История после контрольной точки сохраняется в `recovery` перед откатом;
новая история не содержит дублирующихся шагов.

Состояние содержит оба PDF-буфера, служебные поля и память выходной границы.
Файл может занимать почти столько же места, сколько расчётные массивы.
При атомарной перезаписи временно нужны место под старый и новый файлы,
при чтении — дополнительная RAM под загружаемый массив. Контрольные
состояния проверяют версии lbmpy, pystencils и NumPy и проверены для CPU.

## Результаты и продувки

В окне доступны история Cl/Cd/Cm, среднее сечение размаха, скорость,
давление и завихренность. Ползунок выбирает сохранённый момент времени.
GIF сохраняется без ffmpeg; доступен также вывод скорости в м/с и p−p∞ в Па.
Файл `history.csv` содержит все выборки; разрежается только график в окне.
Времена сил относятся к середине шага обмена импульсом, кадры — к концу
шага. RMS в `summary.json` не является доверительным интервалом.

Вкладка «Продувки» содержит только экспериментальные данные:

- Ohtake et al. (2007), NACA0012, Re=30000: оцифрованный Cl, 115 точек;
  Cd/Cm пока не извлечены. Пределы оцифровки не равны погрешности трубы.
- Ladson NASA TM-4074 (1988), таблица IX, Re=5.95 млн, M=0.15, 80-W:
  17 строк Cl/Cd/Cm(c/4). Этот Re выходит за область текущего ядра;
  таблицу можно просматривать для подготовки следующей модели.

Кнопка сравнения требует завершённого расчёта и проверяет Re, известное
число Маха, угол и одноэлементный NACA0012. Экстраполяция запрещена.
Момент пересчитывается в c/4 с учётом положения исходной точки. Выход
`experiment_*.json` содержит разности и ограничения. Даже совпадение чисел
не подтверждает геометрию модели, условия перехода, стенки трубы или
численную/статистическую сходимость. Итог имеет статус `comparison_only`.

CLI также доступен:

```text
python -m aerokinetic.cli plan examples/naca0012_preview.json
python -m aerokinetic.cli run examples/naca0012_preview.json --output run_01
python -m aerokinetic.cli resume run_01
python -m aerokinetic.cli animate run_01 --field pressure_pa
python -m aerokinetic.cli compare run_01 --reference ohtake_re30000
```

Последняя команда требует подходящего Re=30000; preview с Re=10000 будет
отклонён, без подмены режима. Самостоятельный GUI запускается также через
`python -m aerokinetic.gui`. Для Linux дополнительно нужен системный Tk
и рабочий дисплей. Подробности фактических проверок — в
[отчёте версии 0.2](docs/RELEASE_02_RU.md).
